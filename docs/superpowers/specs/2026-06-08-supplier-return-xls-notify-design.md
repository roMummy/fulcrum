# 供应商回单 Excel 兼容解析与群通知设计

## 背景

142 服务器当前实际处理供应商回单的是独立服务 `/data/supplier-order-admin`，监听 8190。供应商回传的 `(1)单-供应商1-06081145-回单.xls` 已经被 Webhook 识别并创建了回单记录，但文件是 WPS/Excel 二进制 `.xls`，现有解析器只支持插件生成的 HTML `.xls` 和文本表格，导致解析不到 `分单ID、快递公司、快递单号` 列头。

## 方案

1. 回单解析器继续兼容现有 HTML `.xls` 和纯文本表格。
2. 识别 OLE 二进制 `.xls` 文件头后使用 `xlrd` 读取第一张表，转换成统一的二维表格行。
3. 识别真实 `.xlsx` 后使用 `openpyxl` 读取第一张表，避免供应商另存为新版 Excel 后再次失败。
4. 表头不再强依赖第一行，解析时在前若干行中查找同时包含必要列的表头行，减少 WPS 插入空行或说明行带来的兼容问题。
5. 表头和关键字段增加空白清洗：过滤普通空格、全角空格、换行、制表符、不可见空字符和 BOM；分单 ID、快递单号去掉内部空白，快递公司压缩多余空白，避免用户复制粘贴或 Excel 格式字符导致回传失败。
6. 解析服务只返回标准处理结果；群通知放在 MBA Webhook 层，文件回传和文本回传共用同一套结果消息。
7. 只对已经匹配到本项目供应商绑定的群发送通知。未绑定群、非收发单消息继续跳过，避免误发。

## 群通知

回传流程完成后，Webhook 调用 MBA Open API 的普通消息接口，把结果发回原企微群。消息内容包含批次号、供应商、总行数、有效行、无效行、重复行、解析状态、导入状态和错误摘要。

通知发送失败不会回滚回单处理结果，但 Webhook 返回中会带上通知失败原因，方便页面或日志继续排障。

## 验证

1. 用失败的真实回单文件验证 `parse_return_file` 可以读到必要列和快递单号。
2. 重跑失败回单 `#7`，确认回单记录进入解析成功或业务导入失败的后续状态。
3. 确认 Webhook 处理完成后会调用 MBA 群消息接口发送处理结果。
4. 只重启 8190 的 `/data/supplier-order-admin` 服务，不影响 8180 主服务。
