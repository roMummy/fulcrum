# 运营后台信息架构简化设计

## 背景与问题

后台核心资产是群、群友、好友、消息，插件需要在群内启用和配置。现状问题：

1. 同一批消息有 6 处入口（会话列表、会话详情、消息中心、渠道详情、微桥后台消息标签、群详情消息表）。
2. 同一个群有三种页面（消息中心聊天页、群详情资料页、会话详情页），入口不统一，点进去有时是消息有时是详情。
3. 群级插件启停与配置接口只放行 wechat_ipad / wechat_winauto / workwechat，微桥群点击会被 400 拒绝。
4. 群级配置要求手写 JSON，页面直接暴露 mode / effect / action_scope 等开发术语。

## 设计原则

- 一个资产只有一个页面、一个入口。
- 非开发人员看不到技术信息，技术信息收进默认折叠的「技术信息」区。
- 按 AGENTS.md 要求，被替代的旧页面和入口直接删除，不保留跳转、别名或兼容分支。

## 信息架构

主导航：总览、群管理、好友、消息、运营能力、账号接入。开发文档、套餐、企业设置收进右上角账号菜单。

| 资产 | 唯一入口 | 说明 |
|---|---|---|
| 群 | /chatrooms | 跨渠道群列表，支持搜索、渠道与纳管状态筛选 |
| 群友 | 群页面「成员」标签 | 头像、昵称、角色；wxid 弱化 |
| 好友 | /contacts | 跨渠道好友列表，点开轻量详情（头像、昵称、备注、共同群） |
| 消息 | /messages | 唯一完整聊天界面 |

## 群页面（/channels/{id}/chatrooms/{id}，唯一的群页面）

标签按使用频率排序：

1. 插件（默认）：每个插件一行，显示名称、一句话说明、启停开关；展开为按插件声明字段渲染的配置表单（复用 _plugin_config_form.html），不手写 JSON。默认继承机器人设置，群内修改后标记「本群已自定义」，可「恢复默认」。
2. 成员：头像、昵称、角色，「同步成员」按钮。
3. 消息：最近 30 条，「在消息中心打开」跳转。
4. 资料：群名、备注、纳管开关。

页面底部「技术信息」折叠区：群外部 ID、同步状态、观测来源、插件运行状态、最近任务与错误原文。

## 所有指向群的链接收口

微桥后台群标签、渠道详情、总览活跃群组榜、消息中心群会话头部（加「群设置」链接）全部指向群页面。

## 删除清单

- /conversations 与 /conversations/{id} 两个页面及模板、导航子项。
- 微桥后台「消息」标签（改为跳转消息中心的链接）；「群组」「群成员」标签并入群管理，微桥后台保留好友与同步操作。
- 渠道详情「最近消息」整块（换为一行摘要加跳转）。
- 群页面独立的消息表格与分页。

## 后端调整

- 群级插件的启用、停用、重置、配置、模式 5 个接口放开 wechat_webridge。
- 新增跨渠道群列表与好友列表查询，复用 IdentityDirectory 解析昵称头像。

## 验收标准

1. 同一个群无论从哪里进入，落到同一个页面，默认显示插件标签。
2. 微桥群可以启停插件并保存配置，页面上没有 JSON 输入框、没有 mode / effect / action_scope 字样。
3. 消息只有 /messages 一个完整入口，/conversations 访问返回 404。
4. 主导航为 6 项，群管理与好友可用。
5. 技术信息默认折叠。
