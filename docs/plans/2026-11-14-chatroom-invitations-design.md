# 群成员邀请关系与邀请树设计

日期：2026-11-14。用户确认「这轮一起做邀请树」，与公告和角色排序一并交付。

## 已确认的页面结果

- 群详情「成员」新增邀请人一列，显示可核实的成员名称与来源；没有证据时显示「未知」。
- 同一标签增加可展开的邀请关系树，支持逐支展开、展开全部与收起分支；展示直接邀请人数。
- 邀请关系按当前租户、渠道、群及成员 ID 关联，名称仅用于展示。同名成员不合并，退群成员保留。
- 不默认把群主当作所有人的邀请人。上级不在本群快照时以 ID 显示；循环关系明确提示并安全展开。

## 数据及边界

- 当前 iPad 与企微的成员适配器已经接入邀请人 ID；同步时归一保存到 `ChatroomMember.extra_json.invitation`，移除重复的旧邀请人快照键。空字段不抹掉已知关系。
- 当前微桥成员名单和成员变更事件未发现邀请人字段，不新增猜测字段或虚构命令。
- 对真实系统消息中的微信入群 XML，只有同时取得邀请人和入群成员的明确 ID 才记录关系。扫码消息标注「扫码来源」，不混同为直接邀请。仅昵称或普通聊天中的相似文案不记录。
- 渠道成员资料的明确邀请人优先于系统消息，同来源按记录时间更新；重复和晚到的旧消息不覆盖新关系。
- 群资料与成员消息更新必须合并保留已保存邀请关系，避免同步后或成员发言后丢失。
- 新消息在入站主流程中记录，独立于群成员通知开关。完全关闭的群仍遵守既有不采集规则。
- 「补查历史邀请」仅检查本群已保存的最近 2000 条系统消息，补充现有成员关系，不拉取微信历史、不虚构已丢失关系、不改成员状态。返回实际检查和更新数量。

## 架构与验证

新增统一邀请关系服务，处理字段归一、系统 XML、已知关系排序和无递归树视图。成员表与邀请树使用同一份数据。复用现有角色鉴权、CSRF、审计和任务反馈；不增加数据库结构或第三方依赖。

定向验证真实 ID/同名、空字段保留、来源优先、重复与旧消息、扫码、伪造聊天、跨群跨租户、退群及循环/深层树。页面验证只读权限、历史补查、成员列表与树一致，检查桌面及 390px 手机的换行、展开操作和局部滚动。

本轮不部署，不提交原有未跟踪的群功能文件；提交说明如实记录实际轻量验证与真机边界。
