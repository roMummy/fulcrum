# 平台协议服务运维导航设计

## 目标

协议服务属于平台基础设施配置，不应继续占用平台顶级导航。平台员工应从“系统运维”进入，再通过二级导航访问运行监控、协议服务和全局日志。

## 信息架构

- 平台顶级导航保留：平台概览、租户管理、套餐管理、订单审核、平台员工、系统运维。
- 系统运维二级导航固定为：运行监控、协议服务、全局日志。
- 访问协议服务页面时，顶级“系统运维”和二级“协议服务”同时显示激活状态。
- 协议服务 URL 继续使用 `/platform/protocol-services`，本次只调整页面归属和导航层级，不制造无意义的新旧路径。

## 代码归属

协议服务页面和保存动作从平台通用管理 Router 移入平台运维 Router。平台顶级导航使用统一构造函数，平台管理、订单审核和系统运维不再分别复制菜单定义。

## 验证

- 平台顶级导航不再出现“协议服务”。
- 系统运维三个页面均展示完整二级导航和正确激活状态。
- 协议服务平台认证、CSRF、保存和渠道同步能力保持不变。
- 只执行平台导航、运维页面和协议服务相关轻量测试。
