# Windows 本地代理扫码连接器设计

## 背景

微信 iPad 扫码登录需要使用租户用户本地网络中的 SOCKS5 代理完成真实登录。平台代理池只能提供平台出口，不能满足用户必须使用自己电脑或局域网出口 IP 的场景。用户希望登录完成后即可关闭本地连接器，后续账号运行不继续依赖该本地代理。

当前 SaaS 已有单次扫码代理会话，但 `custom` 代理要求 874 服务所在服务器直接访问代理地址，无法访问用户电脑上的 `127.0.0.1` 或不可路由的局域网地址。本设计新增独立 Windows 连接器，通过反向加密隧道把本地 SOCKS5 代理临时提供给一次扫码登录。

## 目标

1. 用户在 Windows 上安装并启动独立连接器。
2. 用户只需首次使用一次性激活码绑定连接器，后续登录无需重复配对。
3. 登录时 SaaS 能使用用户本地 SOCKS5 代理获取二维码、轮询扫码状态并完成登录握手。
4. 连接器断开时当前二维码会话立即失败，不能继续使用半开的登录状态。
5. 874 返回登录成功后，SaaS 清除 874 登录数据中的本地代理，再结束本地隧道。
6. 登录完成后，心跳、消息同步和普通账号运行不依赖用户本地连接器。
7. SaaS 不保存用户本地 SOCKS5 密码，日志、页面和审计不输出代理凭证。

## 非目标

- 不把连接器并入现有企业微信 Provider 账号体系。
- 不让用户开放公网入站端口或配置路由器端口映射。
- 不提供长期通用 SOCKS 代理转发。
- 不让浏览器插件代替服务端 874 的真实代理链路。
- 不让登录成功后的消息、心跳和联系人请求继续通过本地代理。
- 首版只支持 Windows 桌面连接器，不同时建设 macOS、Linux 客户端。

## 方案

采用“独立 Windows 连接器 + 一次激活、长期注册 + 每次扫码临时隧道”。

连接器主动通过 `wss://` 连接 SaaS，因此用户局域网不需要允许外部访问。SaaS 为每次扫码会话创建临时 SOCKS 中继。874 使用该中继的临时地址、用户名和密码；中继校验会话凭证后，把 TCP 连接请求通过 WebSocket 转交给 Windows 连接器。连接器再连接本机 SOCKS5 服务并转发数据。

登录链路为：

```text
Windows 连接器 -> 用户本机 SOCKS5 -> 本地代理出口 -> 微信
                         ^
                         |
874 -> SaaS 临时 SOCKS 中继 <- WebSocket 反向隧道
```

浏览器只负责选择连接器、显示二维码和轮询业务状态，不承载代理流量。

## 用户流程

### 首次绑定

1. 租户管理员在“企业设置 > 本地代理连接器”创建连接器名称。
2. SaaS 生成一次性激活码，只在当前响应中展示。
3. 用户在 Windows 连接器中填写 SaaS 地址、激活码和本地 SOCKS5 地址。
4. 连接器调用激活接口换取设备密钥，并将密钥写入 Windows 受保护配置。
5. 连接器建立 WebSocket，页面显示在线状态。

### 扫码登录

1. 用户在微信 iPad 账号接入页选择“本地代理连接器”。
2. SaaS 只展示当前租户下在线的连接器名称，不展示代理密码。
3. SaaS 创建 `local_connector` 登录代理会话，并签发仅本次会话有效的中继凭证。
4. 874 使用中继地址取二维码。
5. 用户扫码、手机确认；874 后续 `LoginCheckQR` 和登录握手继续使用同一个中继。
6. 874 返回登录成功并保存 `wxid` 后，SaaS 调用 874 `Tools/setproxy` 清空该账号的本地代理。
7. SaaS 确认清理成功后结束登录代理会话，关闭中继，通知连接器释放本次隧道。
8. 用户可以关闭连接器；账号后续运行使用服务器直连或其他已配置的运行期网络。

## 数据模型

新增平台全局或租户归属的连接器实体，首版按租户隔离：

### `proxy_connectors`

- `tenant_id`：可信租户归属。
- `name`：用户可识别名称。
- `status`：`pending`、`active`、`disabled`。
- `device_id`：稳定设备标识摘要。
- `last_seen_at`：最近心跳时间。
- `client_version`：连接器版本。
- `local_proxy_label`：脱敏的本地代理标签，不保存完整凭证。
- `created_at`、`updated_at`、`disabled_at`。

### `proxy_connector_activation_codes`

- 连接器 ID。
- 激活码摘要。
- 过期时间、消费时间、撤销时间。
- 创建人和审计摘要。

### `proxy_connector_credentials`

- 连接器 ID。
- 设备密钥摘要。
- 签发时间、最后使用时间、吊销时间。
- 不保存设备密钥原文。

### `login_proxy_sessions` 扩展

- 新增 `mode=local_connector`。
- 新增 `proxy_connector_id`。
- 保存临时中继凭证摘要、租约和连接状态。
- 不保存本地 SOCKS 主机、用户名和密码。

## WebSocket 与中继协议

连接器 WebSocket 只使用设备密钥认证。文本帧承载控制消息，二进制帧承载 TCP 数据。

控制消息包括：

- `hello`：设备 ID、连接器版本和协议版本。
- `hello_ack`：服务端确认租户和连接器状态。
- `heartbeat`：在线保活和服务端时间。
- `open`：中继请求一个目标连接，包含隧道连接 ID、目标主机和端口。
- `open_result`：连接器返回本地 SOCKS 连接结果。
- `close`：释放单条连接或整个扫码会话。
- `session_end`：服务端要求结束本次登录隧道。

连接器只允许访问它本地配置的 SOCKS5 地址。它不接受服务端任意目标地址，也不暴露本地监听端口。

服务端中继只接受当前登录会话生成的临时用户名和密码，限制连接数量、空闲时间、总会话时长和单连接读写错误。登录会话结束后凭证立即失效。

## 登录完成后的代理清理

874 会把扫码时的 `Proxy` 写入登录数据，后续 `CheckQR` 和登录收尾会继续读取它。登录成功后必须调用 `Tools/setproxy` 发送空代理并等待成功结果，再释放本地隧道。清理失败时不能显示“登录完成并可关闭连接器”，应保留连接器在线并提示重试清理。

Gateway 的登录编排层需要把“登录成功”和“代理清理成功”作为两个独立状态，只有两个状态都完成才结束 `local_connector` 会话。

## 安全边界

- 激活码只保存摘要，默认短时有效且只能消费一次。
- 设备密钥只保存摘要，连接器本地使用 Windows DPAPI 或等价受保护存储。
- 本地 SOCKS 密码只保存在连接器内存和受保护配置，不上传 SaaS。
- 所有连接器接口按设备密钥解析可信 `tenant_id` 和连接器 ID，不接受客户端提交租户归属。
- 连接器只能绑定一个租户，停用或吊销后立即拒绝新的 WebSocket 和扫码会话。
- 日志只记录连接器 ID、会话 ID、状态和稳定错误码，不记录代理密码、完整地址或原始隧道数据。

## 验证范围

首轮只做直接相关的轻量验证：

1. 激活码一次性消费、过期、撤销和跨租户隔离。
2. 设备密钥认证、吊销、心跳和断线状态。
3. 临时中继凭证只能绑定当前扫码会话，终态立即失效。
4. Windows 连接器能连接本地 SOCKS5，并完成二进制数据双向转发。
5. 874 取码、`LoginCheckQR`、登录收尾使用同一中继出口。
6. 登录成功后 `setproxy` 清空代理，连接器关闭后心跳和消息同步仍可用。
7. 连接器断开、扫码超时、取消和清理失败时的回收与提示。
8. 页面不回显激活码、设备密钥或 SOCKS 密码。

真实微信扫码和真实用户局域网代理验收需要在 Windows 设备、可用 SOCKS5 和当前 874 服务上单独记录，不能用单元测试代替。
