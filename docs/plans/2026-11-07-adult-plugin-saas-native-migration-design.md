# 成人内容插件 SaaS 原生迁移设计

## 目标

将 `/data/abot` 中的 `beautyleg`、`video`、`video_man`、`fanhao_search`、`xiuren_image` 和 `sehuatang_push` 六个插件，以当前 Multi Bot SaaS 的目录插件、租户绑定、标准消息、媒体、积分、状态和统一调度能力重新实现。

迁移结果保留原有业务入口和核心功能，但不加载 A-BOT 运行时，不读取 A-BOT 数据库、Redis、微信客户端对象或本机绝对路径，也不增加旧接口、旧字段、旧账号体系或兼容跳转。

## 已确认范围

### 纳入迁移

1. `beautyleg`：随机图片回复、积分消耗和群级频率限制。
2. `video`：随机黑丝视频下载与视频回复、积分消耗和频率限制。
3. `video_man`：随机猛男视频下载、视频首帧处理与视频回复、积分消耗和频率限制。
4. `fanhao_search`：番号查询、JavBus 详情与封面、磁力结果、引用图片查番和结果图片回复。
5. `xiuren_image`：图片抓取、租户资源缓存、随机图片回复和定时资源更新。
6. `sehuatang_push`：定时抓取、JavBus 目录与详情补全、封面样品、PDF 生成和标准文件推送。

### 不纳入本批

- `plugin_manager`、`stats_collector`、`system_updater`、`trendradar_permission`：继续使用现有平台原生能力。
- `pfe_hub`：只有说明文档，没有可运行插件入口。
- `group_assistant`：A-BOT 当前工作树只有编译缓存，且属于 AI 助手能力，不在本次非 AI 插件迁移范围。

## 方案选择

采用 SaaS 原生重构，不采用 A-BOT 兼容适配层，也不把六个插件拆成独立微服务。

兼容适配层会继续暴露全局机器人对象、旧权限枚举、旧 Redis 键、旧数据库表、微信专用发送方法和单机文件路径，无法保证租户隔离，也会形成当前架构明确禁止的第二条业务路径。独立微服务会增加部署、鉴权、媒体传输、任务一致性和观测成本，不适合本批插件的实际负载。

## 总体架构

### 插件目录

每个插件使用当前目录插件协议：

- `config.toml` 声明插件代码、名称、类型、命令、渠道、聊天类型、超时、普通配置和敏感字段。
- `plugin.py` 只实现当前 `DirectoryPluginProtocol` 所需的匹配和处理入口。
- 复杂抓取、媒体处理和结果解析拆分为插件目录内部的纯业务模块，不导入 A-BOT 包。
- 插件默认关闭，由租户在机器人绑定级别启用。

### 通用能力

插件只依赖以下 SaaS 能力：

- 可信入站消息、会话、群成员和引用附件读取。
- 标准文本、图片、视频、文件回复和统一出站队列。
- 租户绑定级插件状态存储，用于缓存水位、重复推送基线、下载元数据和任务游标。
- 租户内积分账本、幂等业务键和频率限制。
- 统一外部 HTTP 客户端，限制超时、响应体大小、重试和敏感日志。
- 统一插件定时任务调度，任务载荷只保存绑定、动作和会话主键等非敏感定位信息。
- 租户隔离的临时文件目录，任务结束后清理并限制文件大小、类型和生命周期。

插件不能直接调用微信、企业微信、Telegram、874 或其他 Provider API，也不能从消息载荷中读取或覆盖租户、机器人、渠道、会话和发送人主键。

### 配置和外部成本

普通配置保存在 `BotPlugin.config_json`，包括：

- 业务开关、命令、积分消耗、频率限制和结果条数。
- 外部站点地址、代理、超时、重试、抓取间隔和资源目录标识。
- 下载大小、图片尺寸、视频时长和 PDF 内容上限。

敏感配置继续使用当前插件密文存储。插件目录只提供空默认值，不保存可用密钥、代理密码或共享账号。

外部站点访问和内容下载产生的成本、代理和可用性由租户绑定配置承担；平台只负责限流、资源上限、审计和失败状态。

## 分批实施

### 第一批：本地资源类

迁移 `beautyleg`、`video`、`video_man`。

- 图片从租户绑定的受控资源目录读取，不使用 `/mnt/nfs_share` 或 A-BOT 项目相对路径。
- 视频下载到租户临时目录，校验响应类型、大小、时长和首帧处理结果后再入队发送。
- 每个请求使用租户、绑定、群会话和发送人组成幂等与限流键。
- 资源不存在、下载失败、格式不支持时只返回业务错误，不暴露本地路径或第三方原始响应。

### 第二批：查询与引用图片

迁移 `fanhao_search`。

- 保留文本番号查询、JavBus 详情、封面和磁力结果。
- 保留引用图片查番，但图片只能从当前租户、渠道、会话和消息关联的附件记录读取。
- 统一外部 HTTP 和图片预处理限制上传大小、图片尺寸、站点响应体和候选数量。
- 代理、镜像站、证书策略和结果展示开关进入租户配置；不在日志中保存完整 URL 中的敏感参数。

### 第三批：图片采集缓存

迁移 `xiuren_image`。

- 将 A-BOT Redis 图片集合改为租户绑定状态和租户文件目录。
- 缓存只保存文件摘要、来源标识、更新时间和有限数量的图片元数据。
- 随机图片请求只返回标准图片回复，缓存为空时创建受控更新任务，不在消息请求中无限抓取。
- 定时更新使用统一插件调度器，下载失败不清空已有可用缓存。

### 第四批：定时抓取和 PDF

迁移 `sehuatang_push`。

- 保留 JavBus 目录抓取、详情补全、封面样品和 PDF 文件推送。
- 统一任务状态、抓取水位、结果摘要和目标会话，避免服务重启重复发送。
- 默认串行抓取，明确设置页面数、影片数、图片数、并发数、请求间隔、重试次数、PDF 大小和保留时间。
- 只有统一媒体出站队列允许发送生成的 PDF；插件不得直接调用渠道发送接口。
- 浏览器或反爬依赖必须先验证当前运行镜像是否具备；缺少运行依赖时明确标记插件不可执行，不引入隐式系统安装或降级到旧 A-BOT 入口。

## 安全和边界

- 六个插件默认关闭，只能由租户机器人绑定显式启用。
- 所有媒体和抓取结果按租户隔离，禁止跨租户路径读取和状态复用。
- 外部下载必须限制协议、主机、超时、响应体和重定向行为，防止 SSRF、超大文件和无限重试。
- 日志只记录插件代码、绑定、动作、状态、大小和稳定错误码，不记录代理密码、密钥、完整抓取正文或原始文件内容。
- 成人内容只作为租户自有插件能力，不加入营销页、公共演示数据、默认套餐描述或平台公共推荐。

## 验收标准

每个插件至少完成：

1. 目录发现、manifest 校验和绑定配置渲染。
2. 命令匹配、租户／机器人／渠道／会话归属校验。
3. 成功回复、外部失败、资源缺失、超时和限流路径。
4. 图片、视频、文件的大小、类型和临时文件清理验证。
5. 定时插件的幂等、重启恢复、租户隔离和失败重试验证。
6. 轻量定向测试、语法检查和 `git diff --check`。

真实第三方站点、代理和 874 发送验收必须单独记录，不能用模拟测试替代。
