# WeBridge 长轮询微信渠道接入设计

## 背景与目标

微桥 WeBridge 8080 是运行在 iPhone 微信内的插件，支持手机内置 HTTP、服务端长轮询和 WebSocket 三种模式。本项目部署在云端 SaaS，无法稳定主动访问每台用户手机，因此采用 WeBridge 服务端长轮询模式。

新增独立渠道类型 `wechat_webridge`，用于承载个人微信账号的消息收发和在线状态。该渠道不复用 `wechat_ipad`：`wechat_ipad` 依赖 874 直连 HTTP API、由平台主动同步消息和管理登录；WeBridge 则由手机主动访问平台，使用固定 `/agent/*` 协议交换事件和命令。

## 方案选择

首期只实现服务端长轮询。手机依次调用 `/agent/register`、`/agent/state`、`/agent/event`、`/agent/poll` 和 `/agent/command_result`。平台在 `poll` 响应中返回待执行命令，不能主动连接手机。

不采用手机内置 HTTP 作为 SaaS 主链路，因为它要求云端直接访问手机局域网地址；不同时实现 WebSocket，因为它会增加持续连接、心跳、断线恢复和多进程连接管理，且当前业务目标不需要这部分复杂度。

## 架构与数据流

1. 租户创建 `wechat_webridge` 渠道，配置 WeBridge 服务端基础地址对应的渠道路径和账号绑定信息。
2. 手机启动后向渠道专属路径发送 `register`，平台按 `device_id`、`session_id` 和 `account_id` 保存运行快照，并确认渠道归属。
3. 手机发送 `state` 后进入在线状态；健康检查读取最近注册/状态时间和插件状态字段。
4. 手机发送 `event` 时，平台验证设备与渠道绑定，使用事件 ID 去重，再转换为统一入站结构并调用现有 `ingest_inbound_event`。
5. 业务出站消息写入渠道专属任务队列；手机的 `poll` 长连接领取命令，命令内容映射为 WeBridge 的 `send_message` 命令。
6. 手机执行完成后发送 `command_result`，平台按请求 ID 幂等完成任务并记录外部消息 ID、状态和错误。

所有运行记录、任务和事件必须按租户及渠道隔离，未知渠道、未知设备或不匹配账号不得降级到其他渠道。

## 首期能力边界

首期支持文本消息入站和出站、设备注册/状态、在线健康检查、事件去重、发送结果回报、失败重试所需的任务保留，以及渠道配置和账号连接验证。

首期不实现图片/语音/视频/文件等媒体命令、朋友圈、红包、收藏、联系人高级操作、群管理高级操作和 WebSocket。协议新增字段允许忽略，但不得把未实现能力伪装成成功。

## 错误与安全处理

- `register` 失败返回非 2xx，阻止后续流程；成功后保存设备和会话快照。
- `state`、`event`、`command_result` 都返回明确 2xx；业务错误写入审计/运行状态，不依赖响应体让插件判断成功。
- `poll` 必须返回 `{"commands": [...]}` 或空对象；等待超时返回空命令列表，避免手机把长轮询误判为失败。
- 设备、会话、账号和渠道不匹配时拒绝处理；事件 ID、命令请求 ID 和结果回报保持幂等。
- 日志只记录设备/账号摘要和请求 ID，不记录授权原文、消息敏感内容或完整凭证。

## 测试与验收

执行与本次改动直接相关的定向测试：渠道目录和配置校验、WeBridge 协议路由、命令入队/领取/完成幂等、事件归一化和去重、账号连接验证，以及 Python 语法检查。完整端到端和真机接收/发送验收在后续接入真实 iPhone 插件后进行，并单独标记为未验证层。
