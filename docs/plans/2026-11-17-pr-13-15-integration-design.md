# PR #13、#15 整合与跨渠道好友聊天设计

日期：2026-11-17。用户已确认审计推荐方案，并明确把 R4 改为支持其他渠道。本文件记录已确认范围，直接进入实施，不再次请求设计确认。

## 最终行为

1. 消息历史、摘要、AI 最近上下文按 `(created_at, id)` 排序，保留 ID 游标；归档可查看，但不进入自动群记忆。保留时间索引迁移。
2. 咕嘎支持引用、媒体、@、原生音乐卡片及渠道实际提供的撤回。撤回只按明确的消息编号或唯一证据定位；未知和歧义事件保留为系统通知，不按正文猜测、不进入插件或 AI。
3. 好友页为具备私聊发送能力的现行渠道开放“发起聊天”。能力由统一渠道目录声明；现行企业微信、iPad、Windows、微桥、咕嘎和 Telegram 发送适配器均有私聊路径。入口仅创建或复用同租户、同机器人、同渠道、同好友的私聊会话，不主动发送消息。
4. 好友须仍为有效好友，渠道和机器人须有效，操作须通过运营角色及 CSRF 校验；跨租户、删除渠道、失效好友不能创建会话。列表按钮与服务端共享能力声明。
5. 心跳和头像补齐保留；空响应不得抹掉有效资料。现有新人头像等待、十分钟旧消息只存档、群插件设置、图谱缩放、插件统计和活动排序保持。
6. QQMusicApi 继续为点歌默认音源。网易云为显式可选音源，相关第三方故障明确报错，不按配置字段猜测音源、不静默切换。卡片展示来源与音源独立。
7. 移除 PR #15 吞掉扫码中继启动 OSError 的改动，保持现有启动行为。测试环境尊重隔离脚本提供的临时数据库；没有受控临时目录时创建唯一目录，禁止误连业务库。

## 整合方式

GitHub 与内网业务主线历史不相交，但共同产品基线的内容已在上轮审计逐文件核对，差异主要为当前已确认的业务增量。先复核内容差异，建立保留当前内容的历史合流，再分别正常合并两份 PR，使双方祖先在最终主线中可追溯。普通快进推送同步两端，不强制覆盖远端；GitHub 必须复核真实 merged 状态，不能把套补丁视为合并。

修复以当前架构为准，不恢复废弃接口、不增加兼容降级路径。用户已有未跟踪的 group_features 草稿不纳入本轮。
