# 全站紧凑筛选工具栏设计

## 目标

把后台查询页面中占据大块首屏空间的筛选卡片统一收敛为紧凑工具栏，让列表、日志和业务数据优先进入可视区域，同时保持桌面和移动端的可用性。

## 改造范围

本次只处理具备明确 GET 查询语义的五个页面：

- 消息列表 `/messages`
- 会话列表 `/conversations`
- 插件清单 `/plugins`
- 平台日志 `/platform/logs`
- 企业微信联系人 `/channels/{channel_id}/workwechat/contacts`

登录、注册、创建、编辑、充值、协议服务和代理池录入等业务表单不属于筛选工具栏，不调整其表单密度。平台大盘现有时间范围分段控件已经足够紧凑，也不重复改造。

## 统一结构

筛选区域统一使用 `compact-filter` 语义，不再复用面向数据录入的 `form-grid`：

1. 筛选表单直接位于结果区域顶部，不再单独占用一张 `filter-card`。
2. 关键词字段使用弹性宽度，枚举选择使用稳定的紧凑宽度。
3. 字段标题在桌面端与控件保持紧密排列，控件高度统一为 36px。
4. 筛选和重置动作与条件同行，避免额外占据整行。
5. 结果数量放入筛选栏附近的简短摘要，不保留重复的说明段落和大块统计卡片。
6. 原有查询参数、提交地址和服务端筛选逻辑保持不变，不增加兼容入口或双路径。

## 响应式行为

### 桌面端

- 筛选条件优先保持单行。
- 关键词输入框承担剩余宽度，选择框保持可扫描的最小宽度。
- 条件过多时允许工具栏自然换为第二行，但按钮始终靠近最后一个条件。
- 页面上方不再出现独立筛选标题、英文 kicker、说明文字和装饰性状态标签。

### 移动端

- 使用原生 `details` 承载筛选条件，默认折叠以优先展示结果。
- 当前存在有效筛选条件时自动展开，避免用户看不到已经生效的条件。
- 展开后字段按单列排列，按钮保持同一操作行。
- 使用原生语义，不引入新的 JavaScript 状态或第三方组件。

## 页面调整

### 消息与会话

删除独立筛选卡片，把筛选工具栏移动到列表表面顶部。消息页原筛选卡片中的四项统计改为列表标题旁的紧凑摘要，只保留总匹配数和当前结果等有效信息。

### 插件

保留插件清单工具栏及刷新动作，把五项查询条件改为紧凑筛选布局。当前显示数量并入筛选摘要，不再单独占据一段正文。

### 平台日志

日志文件概览保持不变。删除独立筛选卡片，把日志文件和关键字条件移动到日志结果表面，并与 Error/Info 标签共同形成紧凑控制区。

### 企业微信联系人

联系人汇总保持不变。筛选工具栏并入联系人列表表面，列表内容紧随其后，减少一个完整业务表面的高度和页面间距。

## 可访问性与约束

- 每个输入和选择框继续保留可见标签。
- 移动端折叠入口使用 `summary`，键盘可聚焦并可原生展开。
- 焦点样式沿用全站 Swiss Style 变量。
- 不用占位符替代字段标签，不通过纯图标隐藏筛选或重置含义。
- 不改变服务端查询、分页、权限和租户隔离逻辑。

## 验证策略

本次以轻量验证为主：

- 在 `tests/test_swiss_ui.py` 中约束五个页面使用统一紧凑筛选语义，且不再使用独立 `filter-card`。
- 检查桌面工具栏尺寸、移动折叠规则和页面横向溢出约束。
- 运行 `tests/test_swiss_ui.py`、相关页面测试、`compileall` 和 `git diff --check`。
- 部署后使用现有平台与企业测试账号检查桌面和移动视口，确认筛选栏、列表首屏和页面横向滚动正常。
