# 群详情导航与本群插件自定义设置设计

日期：2026-11-16。用户已确认采用“圆角分段 Tab + 可展开插件配置卡片”，要求直接实施；手机离线与签到排查按用户要求暂放。

## 当前问题与目标

群详情仍使用独立的蓝色下划线 `.tab-bar`，与当前浅灰背景、白色圆角表面、靛紫强调的 Soft UI 不一致。插件区域仅有群内启停和恢复默认；此前删除原始 JSON 编辑器时同时删除了配置保存入口。

本次恢复面向用户的结构化设置：逐条修改本群指令触发词，调整插件支持的关键词、群内是否需要 @，以及非敏感专属选项。配置仅影响当前群，未覆盖的项目跟随机器人默认值。默认指令与自定义触发词之间必须有明确映射，不能只改变匹配规则而让插件无法执行。

## 已确认页面与交互

推荐方案为卡片内展开设置；另外比较过弹窗编辑和单独设置页，前者减少列表高度但反复打开、后者适合长表单但增加跳转。用户选择沿用现有群功能卡片的展开、开关和保存交互。

- 导航保持群功能、插件、成员、消息、资料的业务顺序，使用共用色彩、圆角与间距。选中态使用靛紫浅底，计数独立显示，手机可在导航自身横向滚动；当前页提供 `aria-current`，消息仍链接唯一消息中心。
- 插件卡片显示真实名称、版本、完整说明、当前生效的指令与配置来源。开关点击即保存，设置区通过按钮展开，保存后就地提示；卡片展开状态按当前群与插件分别保存。
- 设置区优先显示触发方式：每个正式指令分别填写本群触发词，可输入多个词；留空恢复该项默认。配置过新触发词后，仅这些词用于对应业务，不能暗中保留旧命令入口。参数、换行及平台 `/`、`#` 前缀保持原有语义。
- 仅对适用的插件显示通用关键词；有自身触发字段的游戏等插件继续使用其结构化专属字段，不为无固定命令的监听器伪造命令。
- 专属设置复用插件字段声明，按中文分组展示。敏感密钥统一在机器人插件配置中管理，本群页面不回显、不接收或保存密钥。不会恢复 JSON 编辑器或已删除的旧保存路由。
- 保存配置不改变本群启停，也不重新启用全局停用的机器人插件。提供“恢复配置默认”及既有“全部恢复默认”语义，前者保留本群启停选择，后者恢复继承并清除本群覆盖。

## 数据与执行链路

继续使用 `GroupPluginScope.config_override_json`，只保存相对于当前机器人及清单默认值的差异，无数据库迁移。差异序列化保留 `false`、空字符串和空列表，确保关闭图片、清空选填值等操作有真实语义。保存进行租户、渠道、群与插件绑定的完整归属校验、CSRF 与运维角色校验，非法字段、重复指令或与同群其他启用插件冲突的触发词明确拒绝。

通用命令映射采用 `command_overrides`：正式命令映射为本群触发词列表。按最长命令优先匹配，保留其余原文；同插件不同业务不能使用同一个触发词。静态候选同时合并机器人与群配置，动态匹配使用本群触发词，再将命中的文本转换为正式业务命令交给插件自定义匹配器与执行入口。

现有 AI 调度已经通过 `effective_message_content` 给原生插件提供仅存在于内存的消息视图。将该能力移动到共用命令模块，由 AI 与本群自定义指令复用同一实现，并更新调用及测试，不保留 AI 模块别名。转换期间即使插件提交事务，也不能更新真实消息正文；退出时恢复内存原文。原始事件和消息主键不变，奖励与发送幂等键保持当前业务路径。

原生消息与定时执行入口应从可信会话定位当前群并合并其设置，再由绑定密文覆盖敏感字段，修复目录层合并后又在执行边界丢失本群配置的问题。保留现有插件主动回写业务配置的明确行为，不在本次范围改造订阅、跨群转发等数据模型。
