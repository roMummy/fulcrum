# 群聊消息总结运行时重构设计

## 目标

把 `message_summary` 从插件自行读取数据库、接收事件载荷历史和调用固定 Dify 服务的旧实现，重构为 SaaS 原生群聊总结能力。平台依据可信插件执行上下文读取指定会话与时间范围内的消息，插件只负责业务校验、Dify 工作流调用和标准回复生成。

本次保留 A-BOT 最新业务主线：仅群聊可用，命令为 `总结` 和 `summary`，支持 `#总结 2026-04-08` 指定自然日；未指定日期时总结昨天零点至当前时间。最低消息数默认 100 条，租户自行维护 Dify 地址和 API Key。

## 方案选择

采用平台消息服务加数据库感知执行入口。

- 不允许目录插件导入 `SessionLocal` 或 SQLAlchemy 模型。插件无法自行绕过租户、机器人和会话归属校验。
- 不把完整历史消息写入原始事件、任务载荷、执行日志或长期运行状态。消息只在单次执行内由平台查询并传给插件。
- 不增加旧 `日报` 命令、旧技术配置字段、固定服务地址、聊天应用模式或宽松输出解析。

## 组件边界

### 通用消息读取服务

新增 `app/services/plugin_runtime/messages.py`，接收当前租户数据库会话、可信 `PluginExecutionContext`、起止时间和数量上限。

服务必须验证：

1. 当前租户上下文与执行上下文的 `tenant_id` 一致。
2. 插件绑定存在，并且属于当前租户和上下文中的机器人。
3. 目标会话存在，并且属于同一租户、机器人和可选渠道。
4. 会话类型为群聊；本次能力不对私聊开放。
5. 只读取时间范围内的文本消息，按时间和主键稳定排序，并限制最大查询条数。

消息转换为不含数据库对象的不可变记录，包括消息编号、时间、方向、发送者和文本内容。插件收到的格式化文本使用 `发送者: 内容`，不包含原始请求、原始响应或附件内部路径。

### 数据库感知执行入口

`DirectoryRuntimeExecutor` 新增显式 `execute_message(db, request)`。该入口只调用插件的 `execute_message_action(db, request)`，普通插件继续使用现有 `execute_action`，不会因为新增能力获得数据库访问权限。

`execute_binding_message_action` 继续复用绑定配置与敏感配置的可信合并逻辑，但数据库会话只传给运行时执行器。插件入口必须立即委托平台消息服务完成读取，禁止自行拼接跨租户查询。

动态消息派发和插件手工执行都改为通过此入口执行 `message_summary`。删除 `app/main.py` 中针对群总结预先注入 `messages` 的特殊逻辑，避免两条消息来源并存。

### 群总结插件

插件只声明 `总结`、`summary` 两个命令，支持 `/` 和 `#` 命令前缀。命令后的唯一可选参数是 `YYYY-MM-DD` 日期；其他参数直接返回业务错误。

插件根据当前上海时区计算总结范围：

- 指定日期：当天 `00:00:00` 到次日 `00:00:00`，未来日期拒绝执行。
- 未指定日期：昨天 `00:00:00` 到当前时间。

平台消息服务返回的消息少于 `min_messages` 时不调用 Dify。达到阈值后，插件调用租户配置的 `{api_base}/workflows/run`，固定提交 `inputs.text`、`response_mode=blocking` 和稳定用户标识。响应只读取 `data.outputs.text`，不保留完整上游响应。

回复优先生成平台标准图片；图片生成失败时降级为标准文本回复。这是同一业务结果的表现降级，不是旧接口兼容路径。

## 定时执行

群总结加入现有统一调度器，声明两个动作：

- `daily_summary_prepare`：为昨日群聊生成摘要并保存必要结果，默认 03:00。
- `daily_summary`：向目标群推送昨日摘要，默认 09:00。

本阶段先使用现有绑定中明确配置的群会话编号，不自动遍历来源不明的群。任务载荷只保存绑定、动作、会话和非敏感阈值，不保存消息正文、Dify 密钥或完整摘要。Worker 在租户会话中重新读取消息和配置。

预生成结果通过 `PluginStateStore` 保存摘要文本、消息数量、时间范围和可选平台共享图片引用，并设置短期过期时间。推送动作优先读取同一日期缓存，缺失时现场生成。

## 错误与安全

- 上下文缺少会话、会话不属于机器人、私聊调用和日期格式错误均在外部调用前拒绝。
- Dify 鉴权失败、超时、非 JSON 响应和缺少 `data.outputs.text` 分别返回脱敏业务错误。
- 执行结果只保留摘要、消息数量、时间范围和标准回复，不返回消息正文列表。
- 日志、任务载荷和插件状态不得记录 API Key、Authorization、完整 Dify 响应或原始消息载荷。

## 轻量验证

- 消息服务定向测试覆盖租户、机器人、渠道、会话和群聊边界，以及时间范围和稳定排序。
- 插件测试覆盖两个命令、指定日期、默认日期、最低消息数、固定 Dify 请求与唯一 `text` 输出。
- 调度测试覆盖群总结扫描、任务载荷脱敏、会话归属和预生成/推送动作。
- 每个能力独立中文提交，只运行本次改动直接相关的测试；完整插件组合回归留到迁移批次结束后执行。
