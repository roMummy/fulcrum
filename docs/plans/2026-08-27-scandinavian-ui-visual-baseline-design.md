# 北欧运营工作台视觉基线设计

## 背景

当前项目已经使用暖灰白、松绿色、木色和小圆角等北欧风格元素，但登录后的企业后台和平台后台仍保留传统 SaaS 管理界面的高密度卡片结构。参考页面强调大面积自然留白、轻字重、温暖底色和极少的视觉边界；当前界面则通过连续白色工作表面、密集指标格、分隔线和小字号组织内容，因此整体更接近常规运营后台，而不是用户确认的斯堪的纳维亚高级感。

本次不为旧页面或旧视觉结构保留兼容样式。所有页面继续使用当前确认的企业后台、平台后台和营销页面路径，直接收敛到一套清晰的视觉基线。

## 偏差结论

### 字体与排版

- 当前字体栈依赖系统不存在的 `Avenir Next`、`PingFang SC` 和 `Noto Sans SC`，在服务端浏览器中回退为 `DejaVu Sans`，无法稳定呈现轻盈的人文几何感。
- 全局正文基准为 `14px`，且存在大量 `10px`、`11px`、`12px` 标签和说明文字，中文阅读质感偏紧。
- 页面标题、区块标题、导航和卡片标题的字重差异不明显，层级主要依赖边界和容器，而不是排版本身。

### 空间与密度

- 后台工作区顶部和区块间距集中在 `20px` 至 `36px`，参考页面的大区块通常使用 `80px` 以上的纵向呼吸空间。
- 指标、趋势、排行、状态和表单连续排列在独立白色工作表面中，形成卡片墙。
- 数据为空时仍保留大面积卡片框架，页面显得重复且沉重。

### 色彩与表面

- 当前色板接近参考风格，但后台主壳使用冷灰背景，连续半透明白色表面覆盖了暖灰白主色。
- 松绿同时承担导航激活、按钮、边界、状态和图表强调，容易形成单一色调。
- 木色主要出现在很小的英文标签中，没有成为稳定的层级辅助色。

### 边界与交互

- 顶栏、页头、标签页、指标格、表格、列表和状态区同时使用分隔线，边界密度过高。
- 活跃导航使用白色块、下划线和较粗字重三重提示，视觉反馈过重。
- 阴影数量不多，但下拉菜单阴影相对页面其他表面偏强，交互层和内容层的材质语言不一致。

## 设计目标

1. 营销页面、企业后台和平台后台共享同一套字体、颜色、间距、圆角、边界和交互节奏。
2. 后台仍保持日常运营效率，不照搬展示页的极低信息密度。
3. 通过排版、留白和色温建立层级，减少依赖卡片、边界和阴影。
4. 保留表单、表格、状态和风险提示的可读性，不为了风格牺牲业务判断效率。
5. 桌面端呈现安静、轻盈、成熟的运营工作台；移动端保持单列、清晰触控目标和无横向溢出。

## 视觉系统

### 字体

项目自托管适合中英文混排的可变字体资源，避免依赖访问外部字体服务。中文和正文使用清晰的现代无衬线字体，品牌大标题使用更有几何特征的展示字体；字体资源必须有明确开源许可并提供 `woff2` 格式。

- 正文基准：桌面 `15px`，营销正文和重要说明 `16px`。
- 页面主标题：后台 `34px` 至 `38px`，营销首页按首屏构图使用更大字号。
- 区块标题：`21px` 至 `24px`。
- 数据指标：`28px` 至 `36px`，使用轻字重和等宽数字特性。
- 辅助文字：默认不低于 `12px`；只有纯装饰性序号或英文眉题允许 `11px`。
- 正文字重以 `350` 至 `450` 为主，强调文字不超过 `550`。

### 色彩

- 主背景：`#f5f0eb`，作为营销页和后台的共同暖色基底。
- 明亮背景：低透明度暖白，仅用于需要真实边界的控件、表格和重复记录。
- 主文字：`#3d3d3d`。
- 次级文字：使用暖灰褐色，不使用过冷的中性灰。
- 松绿：用于主要动作、正向状态和关键趋势。
- 峡湾蓝：用于信息状态、次级趋势和跨渠道数据。
- 木色：用于眉题、序号和弱化层级。
- 危险色继续保留低饱和红色，不能因风格统一而削弱风险识别。

### 空间

- 后台工作区桌面左右留白使用响应式 `40px` 至 `64px`，最大内容宽度保持现有业务所需的宽屏能力。
- 页面主标题与首个业务区之间使用 `36px` 至 `48px`。
- 页面级业务区之间使用 `48px` 至 `64px`。
- 区块内部标题与内容之间使用 `20px` 至 `28px`。
- 重复记录行保持 `64px` 至 `76px` 的稳定高度，不通过大卡片包裹单行记录。
- 移动端适度收敛为 `24px` 至 `40px`，不按桌面比例机械缩小字号。

### 表面与边界

- 页面级区块默认使用透明背景，不再自动生成白色卡片。
- 只有表单编辑器、对话框、价格方案、风险操作区和真实重复项目可以使用有底色的工作表面。
- 指标区使用连续开放式布局，通过列间留白和轻微色温差建立分组，避免每格完整边界。
- 表格仅保留表头底色、关键横向分隔和行悬停状态，不使用纵向网格线。
- 列表使用开放行布局，行间分隔线透明度低于当前值。
- 圆角保持 `2px` 至 `6px`，不使用大圆角。
- 内容表面默认无阴影；浮层使用极轻、扩散范围较大的阴影。

### 交互

- 颜色和边界过渡使用 `360ms` 至 `500ms`，不使用位移、弹跳和放大。
- 导航激活态只保留文字颜色和一处轻量底色或下划线，不叠加三重强调。
- 按钮保持明确命令语义，主要按钮使用炭黑底，次级按钮使用透明底和暖灰边界。
- 所有交互继续提供 `:focus-visible` 状态，触控目标不小于 `40px`，关键移动端操作不小于 `44px`。

## 页面结构

### 营销页面

营销首页保留现有产品定位、能力、流程、价格和行动入口，不新增解释性模块。优化重点是：

- 首屏品牌名称成为最强视觉信号，产品价值说明退居第二层。
- 首屏减少后台截图与文字的重叠噪声，提高背景图的材质感和层次。
- 能力与流程区从连续短横线改为更开放的编号排版。
- 价格方案保留可比较性，但降低边框和按钮的视觉重量。
- 各大区块使用暖灰白和低透明度暖白交替，不使用纯白硬切。

### 企业后台

- 顶栏降低高度和重量，品牌、主导航、账户入口形成清晰的三段结构。
- 页面标题区取消贯穿全宽的强分隔线，使用留白完成与内容的分组。
- 总览指标改为开放式指标带；趋势、排行和风险仅在有真实业务边界时形成表面。
- 账号、员工、机器人、插件、消息和渠道列表统一使用开放列表或轻表格，不再用嵌套卡片。
- 表单页将输入区域放在单一编辑表面中，说明、状态和历史记录保持无框分区。

### 平台后台

- 与企业后台共享同一壳层和组件基线，通过内容与权限区分平台身份，不创造第二套视觉系统。
- 平台数据大盘使用开放指标带、低饱和趋势图和清晰排行表，避免新增密集卡片。
- 租户、套餐、订单、员工和运维页面统一列表密度、筛选区和状态表达。

## 响应式规则

- 桌面宽度大于 `1100px` 时，指标和数据分析可使用多列网格；区块本身不做浮动卡片。
- 平板宽度下逐步减少列数，优先保持文字和数据完整，不缩小到不可读字号。
- 移动端使用单列布局，顶栏菜单保持现有折叠机制；二级导航允许横向滚动但隐藏滚动条。
- 表格只在自身容器内横向滚动，整页不得产生水平溢出。
- 固定格式的指标、图表和操作区使用稳定的网格轨道或纵横比，加载和空状态不能改变页面结构。

## 实施范围

本轮先完成影响全站的视觉基线和高频页面，避免逐页追加临时覆盖：

1. 全局字体资源与设计 token。
2. 企业与平台共同使用的顶部导航、工作区、页头、标签页、按钮、徽标、表单、表格和列表。
3. 营销首页和价格区域。
4. 企业总览、平台总览、账号接入和员工管理等代表性页面。
5. 使用定向静态检查确保其他页面继续使用共享组件，不保留旧视觉兼容分支。

## 验证策略

按照当前研发阶段的轻量测试策略执行：

1. 更新定向 UI 契约测试，检查字体、背景、工作表面、导航、列表和响应式基线。
2. 执行模板渲染相关测试和 CSS 静态检查。
3. 使用 `1536x864` 与 `390x844` 视口检查营销首页、企业总览、平台总览、账号列表和员工列表。
4. 检查页面无横向溢出、文字不遮挡、二级导航无可见滚动条、按钮和表单保持可操作。
5. 不执行与本次视觉基线无关的完整历史回归。
