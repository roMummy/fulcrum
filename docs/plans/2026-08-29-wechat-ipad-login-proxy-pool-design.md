# 微信 iPad 扫码登录代理池与业务化页面设计

## 背景

当前微信 iPad 874 已支持在获取二维码和登录唤醒请求中传递 SOCKS 代理，但租户首次接入向导没有代理选择能力，渠道详情又混入健康检查、协议状态、二维码链接、探针和原始连接信息等技术内容。平台代理仍依赖渠道长期配置，无法表达“只在本次扫码登录期间使用、下次登录重新选择”的业务规则。

本次将扫码登录重构为企业用户可理解的业务流程，并建设不依赖具体代理供应商的平台通用代理池。平台员工维护可用代理，租户可以按省市智能选择平台代理、填写自有代理或直接登录。

## 目标

1. 平台员工可以在“系统运维 > 代理池”维护 SOCKS 代理。
2. 租户扫码登录时可以选择省市，由系统自动分配附近的健康代理。
3. 租户也可以填写自有 SOCKS 代理，或选择不使用代理。
4. 代理只绑定当前扫码登录会话，不与微信账号长期绑定；下次登录可以重新选择。
5. 二维码生成后到本次登录结束前固定代理，避免登录阶段发生 IP 漂移。
6. 首次接入和账号详情重新登录共用同一套业务化扫码体验。
7. 租户页面不再展示协议地址、UUID、二维码链接、探针、调用结果和调试操作。
8. 代理密码加密保存，不回显、不写日志，不通过页面或接口返回原文。

## 非目标

- 本次不对接任何代理供应商 API。
- 本次不支持 HTTP 或 HTTPS 代理；874 契约要求使用 SOCKS 代理。
- 本次不建设独立代理微服务。
- 本次不允许同一个池代理同时服务多个扫码登录会话。
- 本次不执行全量历史兼容性回归，也不保留渠道长期代理配置的旧业务路径。

## 方案选择

采用“平台内建代理池 + 独立登录代理会话”。

平台代理是平台基础设施，登录代理会话是租户侧临时业务记录。874 客户端只接收会话解析后的统一代理配置，不关心代理来自平台池还是租户自有配置。该方案能够保持单一登录路径，并为后续代理来源扩展提供稳定接口，而不把供应商概念带入租户页面或协议客户端。

未采用以下方案：

- 将代理继续写入渠道适配配置：代理会长期残留，与按登录会话使用的规则冲突。
- 独立代理服务：会额外引入部署、鉴权和故障链路，首版没有必要。

## 数据模型

### 平台代理

新增平台级代理实体，不带 `tenant_id`，由平台员工统一维护：

- 名称。
- 省、市。
- 主机、端口。
- 用户名。
- 加密密码。
- 启用状态。
- 健康状态。
- 连续失败次数。
- 最近检查时间。
- 最近分配时间。
- 最近成功时间和最近失败时间。
- 最近结果摘要。

以“主机 + 端口 + 用户名”建立唯一约束，避免批量导入产生重复代理。代理已经产生登录记录后不物理删除，只允许停用。

### 登录代理会话

新增租户级临时会话实体，必须通过可信租户上下文访问：

- `tenant_id`。
- `channel_id`。
- 登录模式：`direct`、`platform_pool`、`custom`。
- 用户选择的省、市。
- 平台代理 ID，可为空。
- 自有代理主机、端口、用户名和加密密码快照。
- 会话状态：准备中、二维码已就绪、已完成、已失败、已取消、已过期。
- 二维码有效期和会话绝对过期时间。
- 本次自动尝试次数。
- 最近业务错误码和脱敏结果摘要。

会话结束后立即清除自有代理密码密文，只保留地区、脱敏地址、模式和结果用于审计。平台代理密码继续保存在平台代理实体中，不复制到会话记录。

### 删除旧路径

微信 iPad 登录不再从渠道 `adapter_config` 读取或保存代理。现有渠道详情代理编辑字段、提取与合并代理配置的旧调用链及对应旧测试在本次范围内直接删除，不保留双写、别名或隐式降级。

## 通用服务边界

新增独立代理池服务，职责包括：

- 校验和保存平台代理。
- 批量导入标准代理数据。
- 按省市筛选和占用平台代理。
- 保证同一代理同一时间只属于一个有效登录会话。
- 记录端口检查和真实扫码调用结果。
- 连续失败后将代理标记为异常。
- 在会话完成、失败、取消或超时时释放代理。

新增登录代理解析接口，将 `direct`、`platform_pool` 和 `custom` 三种模式统一解析为 874 所需的 `ProxyIp`、`ProxyUser`、`ProxyPassword`。874 客户端不读取数据库模型，也不包含平台代理或自有代理分支。

## 分配与生命周期

1. 租户选择直接登录、智能选择或自有代理。
2. 智能选择只在指定省市中筛选已启用、健康且未占用的代理，不跨地区降级。
3. 数据库事务按“最久未使用”顺序占用一个代理，防止并发重复分配。
4. 系统使用该代理调用 874 获取二维码。
5. 二维码生成前连接失败时释放当前代理，并在同一省市继续尝试，最多尝试 3 个代理。
6. 二维码生成后锁定本次代理，不再自动切换。
7. 用户更换代理时废弃旧二维码、终止旧会话并重新创建登录会话。
8. 登录成功、失败、取消、二维码过期或会话超时后释放平台代理。
9. 会话有效期优先采用 874 返回的二维码有效期，同时设置 10 分钟绝对上限。

平台代理连续失败后自动变为异常状态，不再参与新分配。平台员工完成检查并确认通过后才能重新启用。

## 租户扫码页面

首次接入与账号详情重新登录复用同一业务组件和服务端流程。

### 配置阶段

用户只填写账号名称并选择登录网络：

- 智能选择：选择省、市，系统自动分配附近可用代理，不展示代理账号和完整 IP。
- 自有代理：填写 SOCKS 主机、端口、用户名和密码。
- 直接登录：不使用代理。

页面不出现协议服务地址、API 凭证、设备 ID、登录档位和适配配置。

### 扫码阶段

页面以二维码为主视觉，只展示四种业务状态：

- 正在准备二维码。
- 等待扫码。
- 请在手机确认。
- 登录成功。

辅助信息只显示账号名称、登录地区或“自有代理 / 直接登录”。操作只保留“重新开始”和“稍后处理”。更换网络方式时旧二维码立即失效。

### 账号详情

账号在线时只显示业务状态、机器人归属、额度和最近在线时间。需要重新登录时进入同一扫码流程。健康检查、协议地址、二维码链接、二维码刷新次数、探针、UUID、原始状态摘要和调试动作全部从租户页面移除。

## 平台代理池页面

代理池位于“系统运维”二级导航，不新增平台顶级菜单。

页面包含：

- 代理总数、健康数量、异常数量和当前占用数量。
- 紧凑代理列表：名称、省市、脱敏地址、状态、最近使用时间和最近结果。
- 单条新增、编辑、启用、停用和立即检查。
- CSV 批量导入。

CSV 固定字段为：`名称、省、市、主机、端口、用户名、密码`。导入时逐行校验，按唯一键跳过重复记录，并返回成功、跳过和失败数量。平台代理密码不回显，编辑时密码留空表示保持当前值。

## 安全与隔离

- 平台代理只允许平台员工管理。
- 登录代理会话使用 `TenantOwnedMixin`，所有租户访问都在可信 `tenant_scope` 和 `tenant_session` 中执行。
- `tenant_id` 和 `channel_id` 从服务端会话及当前资源解析，不接受客户端提交归属。
- 代理密码复用项目统一加密服务保存。
- API、模板、日志、审计摘要和异常信息均不得包含代理密码原文。
- 租户只能看到当前登录会话的模式和脱敏信息，不能读取平台池完整代理清单。
- 分配过程必须使用数据库锁或等价原子更新保证独占。

## 异常处理

- 指定地区无可用代理：提示用户更换地区、使用自有代理或直接登录。
- 平台代理连续 3 次取码失败：标记为异常并停止分配。
- 自有代理不可用：提示检查代理信息，不返回 874 原始错误。
- 二维码生成后代理异常：结束本次会话，提示重新开始，不使用新代理继续旧二维码。
- 会话超时：释放池代理、清除自有代理密码并将二维码判定为失效。
- 并发占用冲突：重新选择同地区下一个代理，不把数据库冲突返回给用户。

## 轻量验证

本次只执行与代理池和扫码登录主流程直接相关的验证：

1. 数据库迁移和模型约束检查。
2. 代理新增、加密保存、批量导入、重复识别和停用测试。
3. 同地区分配、单代理独占、最多 3 次重试、完成与超时释放测试。
4. 直接登录、平台代理、自有代理三条扫码路径测试。
5. 二维码生成后固定代理及更换代理废弃旧二维码测试。
6. 租户隔离、平台权限和 CSRF 定向测试。
7. 租户模板不再出现技术字段和调试操作的页面断言。
8. 微信 iPad 874 代理请求契约测试和模板语法检查。
9. 部署后的 `healthz`、`readyz`、平台代理池页面和租户扫码流程验证。

本轮不执行全量历史回归。提交和最终报告必须如实列出实际执行的测试。
