# 欢迎卡片缩略图来源二选一设计

用户确认希望将手填 URL 和新成员头像做成直接选择，沿用当前群功能卡片、统一发送链路及部署到 201 的安排，不再重复询问已明确的交互。

## 方案

采用“缩略图来源”下拉框，提供“自定义图片 URL”和“新成员头像”。默认自定义 URL，保留当前已填写地址。选择头像时隐藏 URL 输入框，但不禁用或清空它，保存和刷新后仍能切回原地址。相比新增多个开关，下拉框能保证来源互斥；相比继续手填变量，选择头像无需记忆占位符。

新增 `card_thumb_source`，值为 `url` 或 `member_avatar`。发送时只按该字段决定缩略图；头像来源使用当前渠道、本群中对应新成员的已同步头像，缺失时正常发送无缩略图卡片，不回退使用自定义 URL。标题、描述和点击网址的现有变量保持支持，原有 URL 模板继续走统一的单次替换，不新增探测配置的兼容分支或第二条发送路径。

通用配置字段已声明 select 类型，本次补齐选项渲染、存储校验与条件可见能力。前后端共享字段声明，页面初次渲染与切换均按同一个来源判断。样式沿用后台输入框和下拉框。

手机真实浏览器验证发现，较长 URL 输入框失焦时会产生横向回滚事件，全局下拉原先将它误认为页面滚动而关闭刚打开的菜单。本次只收紧关闭条件为“页面或触发按钮祖先滚动”，保留页面滚动关闭菜单的行为，输入框与选项列表内部滚动不再误关。

## 验证与发布

定向检查两种来源的保存/刷新、源切换后 URL 保留、头像与成员对应、缺头像不回退、无头像需求不查身份目录、非法选项规整、页面基准和桌面/手机浏览器交互。只运行相关轻量测试，中文提交。从明确提交构建并部署到 201，仅重建 app，保留数据库、私有插件与回滚镜像，不向真实群发送验收消息。
