# 租户与渠道简化接入设计

## 背景

当前平台开通租户需要填写租户编码、企业信息、管理员账号、联系人和备注等多项内容。企业完成注册后，还需要分别理解机器人额度绑定、机器人、渠道和 Provider 节点，才能完成一个外部账号的接入。

这些对象仍然是必要的内部模型，但不应成为租户完成主流程前必须理解的产品概念。租户真正关心的是接入哪个平台账号、账号是否在线、占用了多少额度，以及可以启用哪些运营能力。

## 目标

- 平台创建企业时只填写企业名称、管理员手机号、套餐和可选到期时间。
- 企业通过统一的“账号接入”流程完成渠道选择、账号连接和启用。
- 账号验证成功后自动创建机器人、渠道和额度绑定。
- 普通租户不直接处理 Provider、适配 JSON、内部节点编号等技术概念。
- 保持全局账号唯一、试用设备限制和不可随意换绑规则。
- 核心业务只依赖通用账号连接与能力接口，不依赖具体 Provider 模型。

## 非目标

- 不合并或删除 `Bot`、`Channel`、`BotAccountBinding`、`ProviderNode` 等内部数据模型。
- 不为历史字段增加兼容别名、双写逻辑或旧流程回退入口。
- 不在本轮建设完整的第三方支付、复杂审批流或自动客户端安装系统。
- 不把所有渠道的高级协议参数暴露给普通租户。

## 信息架构

企业后台主导航调整为：

1. 总览
2. 账号接入
3. 运营能力
4. 消息
5. 套餐
6. 企业设置

“账号接入”承接原机器人绑定、机器人、渠道和 Provider 节点的高频操作。内部对象仍可由服务层维护，但不再要求租户跨多个入口手工拼装。

运营能力承接插件开关和账号对应的能力配置。消息继续承接会话和消息记录。套餐继续承接额度、订单和续费。

## 平台租户开通

平台租户列表默认先展示企业清单，通过“开通企业”进入简化表单。表单只保留：

- 企业名称
- 管理员手机号
- 套餐
- 到期时间，可为空

服务端自动完成：

- 生成高熵租户编码。
- 使用固定内部管理员用户名。
- 生成管理员显示名称。
- 将管理员手机号作为默认联系电话。
- 生成只展示一次的初始密码。

租户编码、内部主键、联系人和备注放入租户详情的高级信息，不出现在默认开通表单中。

## 企业账号接入流程

### 第一步：选择平台

页面展示面向业务的渠道入口：

- 个人微信
- 企业微信
- Telegram

个人微信进入下一步后再选择 iPad 协议或 Windows 客户端。协议选择只说明所需连接方式，不展示内部适配器编码。

### 第二步：连接账号

每种渠道只显示完成连接所需的最小字段和动作：

- Telegram：填写 Bot Token，服务端调用账号信息接口验证身份。
- 企业微信：选择已上线账号；没有在线账号时进入客户端激活流程，页面不使用 Provider 作为主标题。
- 微信 iPad：填写协议服务地址和必要凭证后进入扫码登录。
- 微信 Windows：连接 Windows 客户端并验证可用账号。

API Base 在用户确实需要提供地址时改为“服务地址”或“客户端地址”。Webhook、私聊策略、允许名单、代理和适配 JSON 不出现在主流程。

### 第三步：确认启用

账号身份验证成功后，用户只需确认显示名称。服务端在同一事务中：

1. 再次检查订阅与剩余额度。
2. 检查全局 `(adapter_type, bot_account_id)` 唯一绑定。
3. 检查试用设备是否已经领取过试用权益。
4. 创建或完成默认机器人。
5. 创建渠道并关联已验证账号。
6. 创建额度绑定并启用渠道。

默认产品关系为一个已接入账号对应一个机器人和一个主渠道。底层模型仍允许后续扩展多渠道，但首版界面不提供复杂组合操作。

## 通用连接能力

新增不依赖具体 Provider 的账号连接接口。具体渠道实现只负责协议交互，并返回统一结果：

- 连接状态
- 已验证账号类型
- 已验证账号 ID
- 账号显示名称
- 设备指纹摘要
- 下一步动作
- 可展示的错误摘要

核心账号连接服务负责租户权限、订阅、额度、唯一绑定、草稿状态和最终事务。具体适配器不得直接创建商业绑定或修改租户额度。

建议的统一状态为：

- `draft`：已经选择渠道，但尚未完成身份验证。
- `connecting`：正在扫码、等待客户端或验证凭证。
- `verified`：已经获得可信账号身份，等待最终提交。
- `active`：机器人、渠道和绑定已经创建并启用。
- `failed`：本次连接失败，可根据错误继续处理。

状态名称属于连接服务，不要求新增兼容字段。实现时优先复用当前真实模型和结构化配置；只有现有模型无法表达必要状态时才增加新的持久化实体。

## 草稿与额度

连接草稿不占用机器人额度。只有获得可信账号身份并完成最终事务后才占用额度。

扫码或客户端连接中断时保留停用草稿，用户可以继续连接。草稿不得进入后台主动调度，也不得产生发送任务。过期草稿可以由后续轻量清理任务删除。

## 高级设置

账号详情默认只展示：

- 平台与账号名称
- 连接状态
- 机器人额度占用
- 最近在线时间
- 可用运营能力
- 启用或停用操作

管理员高级区域按渠道需要展示服务地址、代理和策略配置。原始适配 JSON 不向普通租户开放；平台排障需要时通过受控运维页面查看。

企业微信执行端节点不再作为“账号接入”的并列标签。节点激活、设备状态和账号发现嵌入企业微信连接步骤，详细节点信息保留在管理员高级区域。

## 列表设计

账号接入首页使用紧凑列表，不再展示十一列协议参数。每行只显示：

- 账号名称与平台
- 连接状态
- 对应机器人
- 最近在线时间
- 额度状态
- 进入详情操作

空状态直接提供“接入账号”主按钮。列表顶部只保留总账号数、在线数和剩余额度三个指标。

## 错误处理

- 凭证无效：停留当前步骤并允许重新填写。
- 客户端离线：显示连接客户端的明确动作。
- 扫码中断：保留草稿，不占用额度。
- 额度不足：阻止最终提交并跳转套餐购买。
- 账号已绑定：拒绝操作，不泄露其他租户信息，提示联系平台处理。
- 订阅失效：允许查看连接信息，不允许启用或执行任务。
- 单一渠道验证异常：只回滚当前连接，不影响租户其他账号。

## 权限与安全

- 只有租户管理员可以完成账号接入、停用和高级配置。
- 运营角色可以查看账号状态和使用已授权运营能力。
- 只读角色只能查看。
- `tenant_id` 始终从可信会话获取，不接受表单或请求体指定。
- 账号 ID 必须来自渠道验证结果，不能由租户手工填写。
- 设备指纹只保存摘要，不在页面回显原值。
- 付费绑定释放仍由平台管理员执行。

## 验证策略

研发阶段只执行直接相关的轻量验证：

- 平台简化开通租户的服务与页面测试。
- 通用账号连接服务的状态和事务测试。
- Telegram、企业微信、微信 iPad、微信 Windows 的定向连接测试。
- 额度不足、重复账号、试用设备重复和订阅失效测试。
- 账号接入列表与分步表单的模板测试。
- 关键页面桌面与移动端基础截图检查。
- Python 语法检查与 `git diff --check`。

本阶段不要求完整历史回归、完整 Playwright 套件或真实第三方账号联调。

## 验收标准

- 平台可以用四项输入开通企业并获得一次性管理员密码。
- 新企业无需手工创建机器人或填写通用账号 ID。
- 企业可以从一个入口完成四类正式渠道的接入。
- 身份验证前不占额度，验证成功后一次性完成机器人、渠道和绑定创建。
- 普通租户页面不再出现适配 JSON、内部节点编号和手填设备指纹。
- 重复账号、重复试用设备和不可换绑规则继续由服务端强制执行。
- 现有商业和调度逻辑继续依赖通用模型与能力接口。
