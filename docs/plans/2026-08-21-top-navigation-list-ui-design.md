# 顶部导航与紧凑列表界面优化设计

## 目标

本轮只调整后台界面的信息组织和视觉表达，不改变平台后台、企业后台的权限边界与业务接口。重点解决桌面侧栏占用空间、二级菜单出现滚动条、员工管理表单挤入表格行以及页面解释性文案过多的问题。

## 后台导航

桌面端移除左侧栏，改为固定在页面顶部的主导航。品牌、主入口、低频入口和当前账号操作位于同一顶部区域：常用入口直接展示，低频入口归入“更多”菜单，账号安全和退出归入右侧账号菜单。平台后台与企业后台继续使用各自的导航数据，不混合权限或入口。

移动端沿用顶部栏语义，点击菜单按钮后展示纵向导航面板。桌面和移动端共用同一份导航项目，避免维护两套链接。被替换的侧栏结构和样式直接删除，不保留旧布局兼容层。

## 二级导航

二级入口使用可换行的紧凑标签导航。桌面端优先单行展示，空间不足时自然换行；移动端同样换行，不再通过横向滚动承载入口，因此页面不出现二级菜单滚动条。当前入口继续使用文字颜色和底部短线识别，不增加额外边框。

## 员工列表

企业员工与平台员工统一为紧凑记录列表，每条记录直接显示账号、姓名、角色或权限、状态等只读摘要。每行右侧提供“更多”操作菜单，编辑操作打开独立弹窗，重置密码等动作仍保持独立提交与原有安全约束。

新增员工表单继续作为独立工作区，不与员工记录混排。移动端记录行按信息块自然换行，操作入口保持在记录右侧或尾部，不使用需要横向滚动的大表格。

首轮排查范围覆盖所有把大段编辑表单嵌入表格单元格的页面。对同类账号、套餐等管理页采用相同的“摘要列表 + 弹窗编辑”语义；纯数据密集型表格不强制改为卡片，避免降低扫描效率。

## 文案治理

删除研发阶段、迁移过程、旧实现兼容、调试方式以及重复解释页面功能的可见文案。页面标题、字段标签和操作按钮直接表达业务含义。

以下内容必须保留：权限边界、安全提醒、额度或绑定限制、操作结果、错误信息、不可逆操作说明、一次性密码提示以及用户完成任务所必需的配置要求。代码注释不属于可见文案，继续按项目要求使用详细中文注释。

## 交互与可访问性

顶部“更多”菜单和账号菜单支持点击外部及 Esc 关闭。弹窗打开后焦点进入表单，关闭后返回触发按钮。菜单按钮和弹窗关闭按钮提供明确的无障碍名称，键盘操作路径与现有弹窗基础能力保持一致。

## 验证范围

按研发阶段策略执行轻量验证：模板语法和定向测试、桌面与移动视口截图检查、菜单与员工编辑关键交互检查。重点确认顶部导航不遮挡内容、二级导航无滚动条、员工列表不产生横向滚动、平台与企业入口未串线。不会在本轮运行完整历史回归。
