# WeBridge 调试日志与微信式消息中心设计

## 目标

为 WeBridge 增加可追踪的交互调试日志，并把消息中心调整为微信式双栏布局：左侧显示会话列表，右侧显示当前会话消息。好友会话展示头像、昵称和最后消息时间；消息详情支持按页向前查看历史消息。XML、App 和卡片类内容需要以可读结果展示，原始 XML 作为可展开详情保留。

## 方案

WeBridge API 在注册、状态、事件、轮询、命令回传和媒体上传边界统一记录 DEBUG 日志；后台同步按钮、命令入队、任务领取、完成和失败记录 INFO/DEBUG 日志，异常使用 ERROR 并包含堆栈。日志字段只包含渠道 ID、任务 ID、请求 ID、命令名、状态和耗时，不记录 Token、设备密钥、完整消息正文或媒体内容。

消息中心继续复用现有 Conversation 和 Message 数据模型。新增聚合查询为左栏提供会话摘要，按最近消息倒序；右栏沿用 conversation_id 查询消息并使用 page/page_size 分页。消息展示层根据 message_type 生成可读摘要，XML 内容显示为结构化标签和字段摘要，原文放进 details 展开区，避免默认页面被 XML 淹没。

## 交互与错误处理

同步命令提交后页面显示任务状态和最近结果；失败时展示后端返回的错误摘要，并可再次发起同步。消息中心在无会话或无消息时显示明确空状态，分页切换保留当前渠道和会话筛选。

## 验收标准

1. 201 应用日志能按渠道 ID 找到一次 WeBridge 请求从入队、轮询到回传的完整链路。
2. WeBridge 异常包含错误码和堆栈，且不泄露认证密钥和消息正文。
3. `/messages` 左侧显示头像、昵称、最后消息时间，点击后右侧显示该会话消息。
4. 右侧消息支持向前翻页，XML/App/卡片内容默认可读，原始内容可展开查看。
5. 现有渠道筛选、消息详情链接和发送入口继续可用。
