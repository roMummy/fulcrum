# 紧凑 Soft UI 全站改造

**Goal:** 将曜枢 AI 双后台与公开站点统一到 Soft UI，优先提高后台信息密度，并重新设计企业、平台登录与注册体验。

**Architecture:** 直接修改现有 Jinja 模板、原生 CSS 和原生交互，替换 Swiss 视觉规则，不增加第二套主题或兼容样式。品牌名称、顶部导航、现有数据和两类身份边界保持现有产品定义。

**Tech Stack:** FastAPI、Jinja、CSS、原生 JavaScript、自托管 Albert Sans / Noto Sans SC。

## 参考与产品取舍

参考来源：`https://www.stylekit.top/zh/styles/soft-ui`，2026-10-21 读取完整 Hard Prompt、Design Spec 与自检清单。

- 采用参考的靛紫主色、slate 浅灰背景、16–24px 主圆角、带色透明柔影、柔和聚焦光环。
- 交互遵循 Cloud Float、Pillow Press、Friendly Viscosity、Halo Focus：按钮轻微上浮、按压回落、300ms 缓动；尊重减少动态效果设置。
- 禁用黑色硬边、纯黑正文、高饱和大色块、硬阴影、默认玻璃模糊、渐变文字和重复英文小标题。
- 用户明确要求商业后台紧凑，优先于参考面向消费类页面的 64–96px 区块留白。后台边距 24px，区块间距 16–20px，卡片内部 18–20px，页标题 26px，列表行 60–68px，筛选控件 36px；触控设备操作目标至少 44px。
- 采用单层业务表面划分分区，指标单独网格排列；图表、表格内部不套多重阴影卡片。
- 认证页采用浅靛色品牌区与白色表单的紧凑双栏，保留明确企业/平台身份；移动端压缩品牌区，优先展示输入框。注册标签与字段同组，修复每个 label/input 独占网格行造成的大量空白。
- 正文使用足够对比度的 slate 文字；品牌色用于焦点、图形与主操作，危险、成功状态各有明确文案。

## 实施步骤

先按 `docs/ui/soft-ui-guidelines.md` 完成调性与规约整理，再依照 `docs/ui/soft-ui-page-checklist.md` 逐页实施和登记证据。下列内容是工程范围，不代表先做完所有共享改动再统一验收。

1. `app/static/css/style.css`：原位替换 token、导航、标题、表面、指标、表格、表单、认证、营销及响应式规则，清理旧风格专用规则。
2. `app/templates/base.html`、`marketing_base.html`：简化重复标题层级，统一认证壳与通知位置，保留现有会话与 CSRF 行为。
3. `enterprise_login.html`、`platform_login.html`、`register.html` 及共享认证局部模板：品牌构图、字段分组、密码可见切换和精简的身份提示。
4. `app/static/brand-mark.svg`、`favicon.svg`：保留 Y 几何与产品命名，适配靛紫配色与圆角。
5. 迁移 `tests/test_swiss_ui.py` 到当前视觉契约，保留导航、身份、价格居中、表格滚动、筛选行为与可访问性检查，删除旧 Swiss 专属断言。

## 验证与交付

- 定向执行 UI、营销页面、公开认证、SaaS 登录测试，使用临时 SQLite，避免触碰部署数据。
- Chromium 核验企业登录、平台登录、注册、平台大盘、企业总览、员工、消息、插件、套餐等代表页面，覆盖 1440px / 1024px / 390px；检查溢出、焦点、表单、移动菜单和弹窗。
- 截图使用隔离预览数据，不能当作生产数据或线上部署证据。
- `git diff --check` 后中文提交，说明实际验证范围；本轮用户请求为 UI 研发，不自动更新 201 部署。
