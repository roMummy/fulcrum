# iPad 874 协议替换设计

## 背景

当前 `wechat_ipad` 已具备二维码登录、状态轮询、心跳、自动恢复、消息收发、联系人同步和群管理能力，但客户端仍保留旧版协议端点与可配置的端点覆盖。旧版登录接口、工具接口及部分请求参数与 `ipad-874` 最新实现不一致，继续沿用会导致取码、状态检查、唤醒登录和健康探针直接失败。

本次以 `https://git.liulabinfo.org/liuwei/ipad-874` 的提交 `d9d3def46f8b5793e4272ba713fcce24c7df6267` 为唯一协议依据，直接替换旧契约，不建立第二套 iPad 渠道，不保留旧端点兼容、回退路由或配置开关。

## 方案比较

### 方案一：在现有客户端中逐处替换字符串

改动量最小，但协议版本、端点和请求格式仍分散在客户端、运行服务和渠道适配器中，后续很容易再次出现路径一致而参数不一致的问题。

### 方案二：新增独立的第二套 874 适配器

可以隔离新旧实现，但会产生两个微信 iPad 入口、两套运行路径和迁移选择，违背当前项目不做兼容性研发及单一业务路径的要求。

### 方案三：建立统一 874 契约并原位替换

将协议来源、版本、默认端口和全部固定端点集中在契约模块中；现有 `wechat_ipad` 客户端、服务和通用渠道适配器只消费该契约。删除旧端点覆盖、无效数据库探针和无鉴权作用的访问凭证字段。

本次采用方案三。它保留现有通用渠道抽象和稳定账号绑定规则，同时彻底移除已经失效的协议路径。

## 架构边界

### 通用渠道层

渠道编码继续使用 `wechat_ipad`，不修改已有命名。账号连接继续通过 `WechatIpadAccountConnector` 输出标准 `VerifiedAccountIdentity`，绑定标识保持为 `wxid`、`device_id` 和 `wechat-ipad-device:{device_id}`，不依赖执行端 Provider 节点。

### 874 契约层

新增 `app/services/wechat_ipad/contract.py`，集中声明：

- 协议仓库地址和已核对的源提交；
- 默认服务地址 `http://127.0.0.1:9064`；
- 登录、消息、联系人、群聊、用户和工具接口端点；
- 端点集合，供契约测试校验旧路径已经完全删除。

契约层只描述固定 HTTP 契约，不读取租户配置，也不承载业务状态。

### 协议客户端层

`WechatIpadApiClient` 统一支持结构化 `query` 参数，由标准 URL 编码生成查询字符串。登录检查、心跳、缓存读取、二次登录和退出使用查询参数；唤醒登录使用 `{"Wxid": ..., "Proxy": ...}` JSON 请求体；其他消息和管理接口继续按 874 Swagger 发送 JSON 请求体。

客户端方法不再接受 `endpoint` 覆盖参数。这样可以确保所有调用只能进入当前 874 契约，旧配置无法把运行时重新导向废弃接口。

### 运行服务层

`service.py` 继续负责二维码生命周期、心跳、自动恢复和消息轮询，但所有跟踪端点直接引用统一契约。登录配置仅保留业务参数，例如登录终端类型、设备标识、代理和同步游标；删除所有 `*_endpoint` 兼容读取。

874 不提供 `/CheckDatabaseOK`，因此操作台和动作分发中直接删除数据库探针。通道健康检查改为 874 心跳与缓存查询，不再构造错误的 JSON 缓存请求。

### 配置界面

微信 iPad 协议只要求协议服务地址，默认提示端口改为 `9064`。874 当前没有 API Token 鉴权，因此从该渠道的配置字段和连接表单中移除访问凭证输入；其他需要 Token 的渠道不受影响。

## 数据流

1. 租户创建 `wechat_ipad` 连接草稿并填写 874 服务地址。
2. 平台调用 `/api/Login/LoginGetQR` 或 `/api/Login/LoginGetQRCar` 获取二维码。
3. 平台通过 `/api/Login/LoginCheckQR?uuid=...` 轮询登录状态。
4. 登录成功后保存 874 返回的 `wxid`、`device_id` 和账号展示信息。
5. 运行时通过心跳、缓存查询和消息同步维持单一协议会话。
6. 通用渠道适配器使用 874 消息端点发送内容，并把回执归一化为平台标准结果。

## 错误处理

- HTTP 失败、非 JSON 响应和 874 业务错误继续进入现有统一错误上下文。
- 查询参数通过标准编码处理，避免 `wxid`、UUID 或代理字段破坏 URL。
- 不识别旧端点配置，也不自动降级到旧协议。
- 缺少真实 874 服务时，明确区分契约级验证与真实扫码、心跳、收发消息验收。

## 测试范围

本阶段按轻量测试策略执行：

- 新增 874 契约单元测试，锁定源版本、端点、默认端口、查询参数和 JSON 请求体；
- 验证旧端点、端点覆盖和数据库探针已经删除；
- 运行账号连接、渠道目录、渠道运行时及相关页面的定向测试；
- 构建应用容器，验证 `8280` 的 `healthz`、`readyz` 和关键页面。

由于当前没有可用的真实 874 协议服务，本次不宣称完成真实微信扫码和消息收发验收。
