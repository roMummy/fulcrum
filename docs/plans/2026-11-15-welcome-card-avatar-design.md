# 新成员欢迎卡片头像变量设计

用户要求在群功能的新成员通知中增加新人头像变量，供欢迎卡片直接使用头像资料。沿用当前“群成员变更提醒”的表单和统一链接卡片发送链路。

## 实现方案

新增 `{avatar_url}`，与 `{nickname}`、`{now}` 使用同一个模板替换入口，标题、描述、点击网址和缩略图地址均支持变量。用户在“缩略图地址”填写 `{avatar_url}` 后，按本次加入成员的明确 ID 从现有 `IdentityDirectory` 读取当前渠道、本群成员头像，成员未同步头像时使用该渠道好友资料。不会使用邀请人、机器人、事件发送者或别的群的成员资料。

当前缩略图字段完全没有模板替换，只加说明无法完成发送。采用统一模板替换和已有身份目录；不拼接 wxid 推测头像、不建立单独的头像上传/代理服务，也不改变现有缩略图为空时的配置行为。

只有启用欢迎卡片并实际用到 `{avatar_url}` 时才查询资料，仍最多发送三张欢迎卡片。缺失或不合法的头像替换为空，正常发送无缩略图的欢迎卡片，不让一名成员头像异常影响其他新成员。成员资料首次尚未同步时不保证本次卡片包含头像，也不重复补发卡片。

## 页面与验证

更新现有字段说明，明确“填 {avatar_url} 使用新人头像”，保留自定义 http(s) 图片地址选项。用户原有配置不自动改写。使用定向单元测试覆盖成员/好友头像、群和渠道边界、多人卡片、头像缺失或异常、单次变量替换及缩略图到微桥 `send_link_card` 的透传；检查实际页面保存和渲染，不运行全量回归。按仓库要求以中文提交。
