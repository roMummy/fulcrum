# 平台托管 iPad 协议服务设计

## 背景

当前微信 iPad 接入要求租户填写协议服务地址。该字段属于平台基础设施配置，不是企业用户能够正确判断的业务信息，也会暴露内部部署结构并产生大量误配置。

本次将 iPad 874 服务地址收归平台后台维护。租户只选择 iPad 接入方式、填写账号名称并扫码，不再接触协议地址或凭证。874 当前没有 Token 鉴权，因此本次不创建无效凭证字段，也不保留租户地址输入的兼容路径。

## 方案

新增平台级 `PlatformProtocolService`，以稳定渠道编码作为唯一键，保存协议服务地址和是否开放新接入。渠道目录增加 `platform_managed_endpoint` 标记，运行流程通过该通用能力判断地址是否由平台托管，不在账号连接服务中硬编码页面行为。

首期只为 `wechat_ipad` 启用该能力。Telegram Token 属于具体机器人账号，Windows 微信仍依赖租户侧客户端，因此两者继续使用各自现有连接方式。

## 数据与流程

1. 平台员工在“协议服务”页面维护 iPad 874 服务地址和开放状态。
2. 平台保存地址时，同步更新所有 `wechat_ipad` 渠道的 `api_base`，保证已有账号与新账号使用同一平台配置。
3. 租户进入 iPad 接入页时只看到账号名称，不显示地址或凭证。
4. 创建连接草稿时，服务端忽略请求中夹带的 `api_base`，读取启用的平台协议服务。
5. 平台未配置或停用新接入时，创建连接返回明确错误，不降级到默认地址或租户输入。
6. 渠道高级设置保留平台写入的地址，但不向租户展示或允许修改。

## 边界

- 本次不自动部署 iPad 874 进程，也不生成协议自身不支持的 Token。
- 本次使用一个平台级服务地址，不实现多节点调度、容量权重或故障切换。
- 后续扩容时可以把同一模型升级为服务池，但不能重新把基础设施地址下放给租户。
- 账号绑定仍使用 `wxid`、`device_id` 和设备摘要，不依赖 Provider 节点。

## 错误处理

- 地址必须是 `http` 或 `https` URL，且必须包含主机。
- 未配置时返回 `platform_protocol_service_missing`。
- 已停用时返回 `platform_protocol_service_disabled`。
- 平台表单错误只返回业务提示，不写入渠道或审计记录。

## 验证

- 平台服务保存、地址校验和渠道同步的定向服务测试。
- 平台页面登录、CSRF 和保存流程测试。
- 租户 iPad 页面不包含地址、Token 或协议配置字段。
- 伪造 `api_base` 不能覆盖平台地址。
- 运行迁移语法检查和本次相关轻量测试。
