# 全站 Swiss Style 视觉设计

## 背景

当前营销站点、注册登录页、企业工作台和平台管理后台已经共享一套 Scandinavian 视觉基线。该基线使用暖灰背景、低透明度白色表面、轻字重和弱边界，能够保持安静和克制，但在数据密集的 SaaS 场景中产生了两个明显问题：一是页面分区主要依赖留白，业务模块在空数据情况下容易连成一片；二是全站色彩对比和视觉节奏偏弱，品牌与关键操作缺少鲜明记忆点。

用户确认将全站统一切换为实用型 Swiss Style。新设计以严格网格、无衬线排版、黑白灰高对比和少量高纯度信号色为核心，同时保留 SaaS 后台所需的信息密度、表格扫描效率和移动端操作能力。本次直接替换旧视觉路径，不提供主题切换、旧 token 别名或 Scandinavian 兼容样式。

## 设计目标

1. 营销站点、认证页面、企业工作台和平台后台使用同一套 Swiss Style 设计系统。
2. 通过网格、硬边界、色块和排版建立清晰分区，解决当前页面过素和模块混在一起的问题。
3. 保留真实产品界面素材、现有业务数据、表单字段、链接、权限和交互流程。
4. 不照搬平面海报的大面积空白，后台继续适合高频运营、扫描、比较和操作。
5. 不增加前端框架、字体服务、图表库或主题运行时，继续使用当前模板与原生 CSS。

## 视觉系统

### 色彩

全站使用 StyleKit Swiss International 参考色调：

- 页面背景：`#FAFAFA`；
- 内容表面：`#FFFFFF`；
- 次级表面：`#F0F0F0`；
- 主文字和强边界：`#0A0A0A`；
- 次级文字：`#5F5F5F`；
- 信号红：`#FF0000`；
- 信息蓝：`#0057B8`；
- 警示黄：`#FFCC00`。

黑色承担主要命令、正文和结构边界。红色承担品牌信号、当前导航、关键行动和重要数据强调。蓝色用于在线、信息和次级数据趋势。黄色用于需要关注但尚未失败的状态。危险操作继续使用红色，但必须同时通过按钮文案、确认弹窗和状态文字表达语义，不能只依赖颜色。

### 字体与排版

继续使用项目已自托管的 Albert Sans 与 Noto Sans SC，不增加字体依赖。Albert Sans 负责品牌、数字和英文标签，Noto Sans SC 负责中文正文。

- 后台页面标题：桌面 `38px` 至 `44px`，移动端 `30px` 至 `34px`；
- 营销首屏品牌标题：桌面 `72px` 至 `88px`，移动端 `52px` 至 `60px`；
- 区块标题：`22px` 至 `28px`；
- 正文：`15px` 至 `16px`；
- 数据指标：`30px` 至 `38px`；
- 分类标签：`11px` 至 `12px`，使用英文、编号或短中文，不增加说明性段落。

所有文字保持左对齐，字间距统一为零。层级依靠字号、字重、色块和网格位置建立，不使用装饰性字距。

### 网格与空间

桌面页面以 12 列思路组织，现有 CSS Grid 根据业务内容使用 `8/4`、`7/5`、`6/6`、`4/4/4` 等比例。移动端收敛为 4 列思路并按业务顺序单列排列。

- 全站内容最大宽度继续为 `1280px`；
- 后台工作区上下留白压缩到适合运营场景的 `40px` 至 `64px`；
- 页面级区块间距为 `40px` 至 `52px`；
- 表面内部间距为 `24px` 至 `32px`；
- 移动端内部间距为 `18px` 至 `22px`。

同一业务组使用较小内部间距，不同业务区通过背景、顶部规则和外部间距明确分开。

### 表面与边界

Swiss Style 不使用当前半透明暖白表面。内容区域改为纯白或纯灰实体表面，并通过 `1px` 黑色边界、`3px` 至 `4px` 黑色顶部规则或红色信号条建立结构。

普通页面区可以保持无框，但所有独立业务模块必须具备明确的标题边界或表面边界。编辑器、弹窗、价格方案、指标带、数据分析区和重复项目使用直角表面。全站圆角收敛为 `0` 至 `2px`，不使用内容阴影；只有下拉菜单和模态浮层允许极轻阴影。

禁止渐变、玻璃模糊、装饰光斑和无业务意义的几何背景。营销首屏可以使用红色矩形作为结构层，但必须与真实产品截图共同表达产品，不生成纯装饰插画。

## 全局组件

### 顶部导航

营销站点和双后台顶部栏统一使用白色背景、黑色底边和紧凑的 12 列对齐。品牌方形标记改为红底白字。当前导航使用红色顶部或底部信号条和黑色文字，不再使用柔和白色块。

移动端菜单继续复用现有单一导航数据和折叠结构。展开菜单使用白色实体表面和黑色边界，不显示横向滚动条。

### 按钮与链接

主要命令默认使用黑底白字；关键转化行动使用红底白字；次级命令使用白底黑边；危险命令使用红底白字并保留确认流程。按钮为直角，最小高度继续满足桌面和触控要求。

文字链接使用黑色并通过底部规则或红色箭头表达可操作性，不依赖低对比绿色。

### 表单与弹窗

输入框使用白底、黑色边界和红色聚焦边界。标签位于输入框上方，错误信息使用红色文字与明确提示。弹窗使用白色实体表面、黑色边界和黑色标题规则，不保留大圆角或玻璃效果。

### 状态与徽标

运行中、在线和信息状态使用蓝色；警告使用黄底黑字；错误、停用和危险使用红色；中性状态使用灰底黑字。徽标为直角小标签，不使用胶囊形状。

### 表格与列表

表格顶部使用黑色强规则，表头使用浅灰背景和黑色文字，行间使用低对比灰线。只保留必要横向边界，不添加纵向网格线。列表继续使用开放行结构，但每组列表必须有明确的黑色顶部规则和稳定行高。

## 页面设计

### 营销站点

营销首屏采用 `8/4` 或 `7/5` 网格。左侧以“曜枢 AI”为最大视觉信号，价值主张和行动按钮依次排列；右侧保留真实后台截图，以黑色硬边界承载，并加入单一红色结构块增强品牌记忆。截图必须保持可辨识，不做模糊、深色遮罩或无意义裁切。

能力、流程和价格区使用编号、强标题、黑色规则和灰色分区组织。价格方案改为硬边界比较结构，推荐套餐用红色信号条标记，不使用柔和悬浮卡片。页尾行动区使用黑底白字与红色按钮，形成明确结束段。

### 注册与登录

企业登录、平台注册和其他认证页不再使用居中浮动卡片。页面使用 `5/7` 或 `4/8` 分栏：品牌上下文使用红色或黑色实体区，表单使用白色实体区。平台管理员入口与企业入口继续保持现有独立路径、文案和会话边界。

移动端按品牌区、表单区顺序堆叠，表单控件全宽，不新增身份说明长文。

### 企业工作台

企业总览的核心指标使用连续白色网格带，并通过黑色顶部规则和红色关键指标建立层级。趋势、排行、风险、状态和机器人总览分别形成清晰业务分区，双列区域使用统一表面高度，不嵌套卡片。

账号、员工、渠道、插件、消息和企业设置页面复用新的表格、列表、表单与弹窗基线，不逐页创建独立主题覆盖。

### 平台管理后台

平台概览使用五个清晰的数据区域：核心指标、双趋势、采用与经营、渠道与租户排行、健康与在线状态。各区域通过白灰实体表面和黑色顶部规则分开；内部图表、漏斗、表格和统计项保持单层结构。

租户、套餐、订单、员工和运维页面使用同一套 Swiss 列表与编辑表面。跨租户平台身份、权限、数据和操作路径保持不变。

### 数据图表

消息、活跃和插件趋势使用红、蓝、黄三种明确色值。图表基线和网格线使用黑色或灰色，图例为直角标记。空数据仍保留稳定尺寸，但通过灰色表面和简短空状态避免出现大面积无结构留白。

## 响应式规则

1. `1100px` 以下逐步减少指标列数和双列业务区，不缩小到不可读字号。
2. `820px` 以下顶部导航折叠，营销与认证分栏改为单列，大盘图表改为单列。
3. `560px` 以下按钮和时间切换控件使用整行布局，指标保持两列或按内容切为单列。
4. 表格只允许在自身 `.table-scroll` 内横向滚动，页面根节点不得水平溢出。
5. 任何文字、按钮、徽标和数字不得遮挡或越出容器。

## 实施范围

本轮直接替换全站视觉基线，主要修改：

1. `app/static/css/style.css` 的 token、全局组件、营销、认证、后台、大盘和响应式样式；
2. `app/templates/marketing_home.html` 的 Swiss 首屏与分区结构；
3. 认证模板的分栏表面语义；
4. 企业与平台大盘模板的业务分区外层；
5. `tests/test_scandinavian_ui.py`，删除 Scandinavian 契约并改为 Swiss Style 契约，测试文件同时按当前设计语义重命名。

不修改业务服务、数据库模型、认证逻辑、路由和数据口径。

## 验证策略

1. 执行 Swiss Style 定向静态测试，检查色板、直角边界、全站模板结构和响应式规则。
2. 执行营销、认证与双后台相关的轻量模板测试。
3. 使用 `1536x960` 与 `390x844` 视口核验营销首页、企业登录、平台注册、企业总览和平台大盘。
4. 检查页面根宽度、关键控件边界、表格滚动、导航折叠、图表尺寸和文字完整性。
5. 部署后验证应用健康、就绪状态和生产页面真实渲染。
6. 不执行与本次视觉重构无关的完整历史回归。
