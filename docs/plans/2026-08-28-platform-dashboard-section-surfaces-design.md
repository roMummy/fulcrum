# 平台大盘分区表面设计

## 背景

平台数据大盘已经包含核心指标、消息趋势、活跃趋势、SaaS 使用漏斗、订阅经营、渠道运行、租户排行、租户健康和在线状态等完整运营内容。当前模板也使用 `.page-section` 标记了各个业务模块，但北欧视觉基线将通用页面区定义为透明背景、零内边距和零边框，导致这些结构分组没有形成可见的视觉边界。

生产页面核验显示，桌面端八个业务区块和移动端对应单列区块均直接落在 `#f5f0eb` 页面背景上，只依赖 `44px` 至 `56px` 的外部间距区分。空数据较多时，趋势图、漏斗、表格和状态列表会呈现为一张连续长页面；顶部核心指标带因为拥有浅白背景，反而成为全页唯一清晰的内容表面。

本次不恢复全站卡片墙，也不修改通用 `.page-section` 语义。平台大盘使用专用分组表面表达业务边界，其他列表页、详情页和企业后台继续保持当前开放布局。

## 目标

1. 让平台大盘的主要业务区域在桌面和移动端都能被快速识别。
2. 保留已确认的北欧暖灰背景、轻字重、小圆角和低边界视觉语言。
3. 不给每个指标、图表、表格行或统计项单独增加卡片。
4. 通过分组背景和内边距建立层级，不依赖阴影、密集边框或装饰线。
5. 保持现有数据、链接、筛选条件、表格滚动和响应式业务行为不变。

## 分组结构

### 核心指标带

核心指标继续使用单一连续数据带，不拆分成十张指标卡。指标带与后续分析区之间保持清晰间距，并适度提高表面明度，使其承担首屏总览语义。

### 趋势分析表面

消息趋势与活跃趋势放入同一个“大区块表面”。桌面端内部继续双列，移动端内部改为单列。两个图表不再拥有各自独立背景，只通过网格间距和标题区分，避免形成嵌套卡片。

### 采用与经营表面

SaaS 使用漏斗和订阅经营放入同一个“大区块表面”。两者都描述租户从注册、订阅到实际使用的经营过程，属于同一运营判断链路。桌面端保持双列，移动端按漏斗、订阅顺序排列。

### 渠道运行表面

渠道运行情况使用独立表面。表格仍保留现有开放表头和横向滚动容器，分区表面只负责标题、表格与页面背景之间的业务边界，不再给表格增加第二层外框。

### 租户排行表面

租户使用排行使用独立表面。排行与渠道表格的数据维度和操作入口不同，不与渠道运行合并，避免宽表在同一表面中形成过长的信息区。

### 健康与在线表面

租户健康情况和在线状态放入同一个“大区块表面”。左侧表达需要平台介入的租户，右侧表达当前系统在线能力，两者共同构成平台运行健康判断。移动端按健康清单、在线状态顺序排列。

## 视觉规则

1. 大区块表面使用现有暖白透明度体系，背景需明显区别于 `#f5f0eb`，但低于编辑器和对话框的强表面。
2. 圆角固定为现有 `6px`，不新增大圆角。
3. 默认不使用阴影，不增加完整描边；区块边界主要由表面色差和内外间距表达。
4. 桌面端表面内边距使用 `30px` 至 `34px`，移动端收敛到 `20px`。
5. 大区块之间使用统一间距，双列内部使用比区块间距更小的网格间距，明确“同组内容”和“不同业务区”的层级关系。
6. 区块内部 `.page-section` 必须重置外边距和背景，防止出现嵌套卡片或重复留白。
7. 核心指标、图表、漏斗、汇总项、表格和健康列表的现有细分边界保持克制，不额外增加纵向网格线。

## 模板结构

平台大盘新增专用 `platform-analytics-surface` 外层，不复用 `.work-surface` 或 `.panel`。原因是该表面只服务分析大盘的业务分组，不应扩大通用工作面板语义，也不需要兼容旧模板。

结构收敛为五个表面：

1. `platform-analytics-trends-surface`：消息趋势、活跃趋势；
2. `platform-analytics-operations-surface`：SaaS 使用漏斗、订阅经营；
3. `platform-channel-summary`：渠道运行；
4. `platform-tenant-rankings`：租户排行；
5. `platform-analytics-health-surface`：租户健康、在线状态。

渠道运行和租户排行现有 section 直接增加表面语义；三个双列组合使用外层 section 包裹内部网格。这样模板只保留一条明确的分组路径，不增加旧类名别名或双重样式入口。

## 响应式

桌面端三个组合表面内部使用双列布局。`1100px` 以下经营与健康区域切为单列，`820px` 以下趋势区域也切为单列，沿用当前图表纵横比和表格自身滚动规则。

移动端每个大区块使用完整宽度和 `20px` 内边距，内部网格间距收敛为 `36px` 左右。页面根节点继续禁止横向溢出，时间范围切换保持当前已验证的满宽布局。

## 验证策略

1. 更新北欧 UI 定向测试，约束平台大盘必须存在五个专用分组表面，并禁止回退到通用工作卡片。
2. 执行平台大盘相关静态测试和 `git diff --check`。
3. 使用已部署测试账号在 `1536x864` 和 `390x844` 视口生成整页截图。
4. 检查五个表面均具有可见背景、稳定内边距和 `6px` 圆角，内部 page section 不重复产生背景。
5. 检查整页无水平溢出、表格只在自身容器滚动、移动端标题和数据不遮挡。
6. 不执行与本次视觉分区无关的完整历史回归。
