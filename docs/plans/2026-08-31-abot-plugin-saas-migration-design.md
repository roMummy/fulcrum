# A-BOT 插件 SaaS 原生迁移设计

## 目标

以 `/data/abot` 当前 `feature-855` 分支为业务来源，逐个核对并迁移最新插件能力到 Multi Bot SaaS。迁移结果必须运行在现有多租户、机器人、渠道和任务体系中，不引入 A-BOT 兼容层，不继续依赖单机微信客户端、全局 Redis、A-BOT 数据库或进程内插件管理器。

本次迁移同时解决插件外部成本归属问题。需要 LLM、Dify、图片生成、MaiBot、Codex 配额服务或其他第三方接口的插件，由租户维护自己的服务地址与密钥；平台负责安全保存、运行调度、限流和审计，不提供隐式公共密钥兜底。

## 已确认范围

### 已有插件

当前 SaaS 已存在 21 个与 A-BOT 同名的插件。它们不按“已经迁移完成”处理，而是逐个对照 A-BOT 最新实现，核对命令、业务规则、外部接口、定时动作、媒体回复和状态数据，补齐当前主流程缺失的能力。

## 方案选择

采用 SaaS 原生重构式迁移。

不采用兼容适配器。兼容适配器虽然可以较快加载 A-BOT 的 `MessagePluginInterface`，但会继续传播全局机器人对象、微信专用发送方法、A-BOT 权限枚举、全局 Redis 键和旧数据库访问，不符合当前架构和“删除兼容路径”的编码要求。

不拆分独立插件微服务。当前插件数量和负载可以由现有 FastAPI、SQLAlchemy、目录插件和任务队列承载，单独引入插件服务会增加部署、鉴权、观测和数据一致性成本。

## 总体架构

### 插件定义与租户绑定

`Plugin` 继续作为全局目录定义，只保存插件代码、展示名称、类型、版本、说明和默认启用状态。

`BotPlugin` 继续作为租户拥有的实际绑定，确定插件属于哪个机器人、是否启用、普通配置、敏感配置和运行状态。插件代码不得自行接受或覆盖 `tenant_id`、`bot_id`、`channel_id` 和绑定 ID，这些主键只能由可信执行链路注入。

### 配置分层

插件配置分为两部分：

1. 普通配置继续保存到 `BotPlugin.config_json`，包括服务地址、模型名称、超时、命令、阈值、显示数量和业务开关。
2. 敏感配置保存到新增的 `BotPlugin.secret_config_encrypted`，包括 API Key、Token、密码、管理密钥和授权头。

目录 `config.toml` 只声明字段及空默认值，不保存任何可用凭证。配置 schema 根据敏感字段声明决定表单渲染和保存位置，不依赖运行时关键词猜测作为唯一判断依据。

### 密钥加密

新增独立的插件密钥封装服务，使用 AES-GCM 对敏感 JSON 整体加密。部署环境通过 `ABOT_PLUGIN_SECRET_KEY` 提供独立主密钥，代码库、数据库和日志中不得出现该主密钥。

每份密文使用随机 nonce，并以 `tenant_id`、`bot_plugin_id` 和密文版本作为附加认证数据，防止把一个租户或插件绑定的密文复制给另一个绑定使用。新插件密钥只支持当前密文格式，不增加历史明文、旧算法或无密钥降级分支。

现有插件配置里的内置共享凭证全部删除。数据库中已经存在的敏感配置不继续读取，部署迁移时统一清除并要求租户重新录入，避免把无法确认归属的共享密钥转存为租户密钥。

## 通用插件能力

迁移插件只能依赖当前项目提供的抽象服务：

- 消息查询：按可信租户、机器人、渠道、会话和时间范围读取消息。
- 联系人与群成员：读取标准化联系人、群和群成员信息。
- 积分账本：查询余额并用幂等业务键完成奖励、扣减和转账。
- 插件状态存储：保存插件业务状态，不使用 A-BOT Redis 键或全局单例。
- 外部 HTTP：统一超时、响应大小、重试、代理和敏感日志清理。
- 出站消息：生成标准文本、图片、文件、视频和引用回复，由渠道适配器完成发送。
- 任务调度：创建租户归属明确的插件任务，由现有 `TaskJob` Worker 执行。
- 媒体与报告：使用租户隔离的数据目录生成和清理临时文件。

插件不得动态注册 FastAPI 路由。复杂外部系统继续通过当前 Open API 或 Webhook 接入；插件后台只使用统一插件详情、绑定配置和运行记录页面。

## 消息执行流程

1. 渠道适配器把入站消息标准化并落库。
2. 插件目录根据机器人绑定、渠道类型、聊天类型、消息类型和群作用域生成候选列表。
3. 执行器从可信会话加载 `BotPlugin`，解密该绑定的敏感配置，并仅在内存中合并有效配置。
4. 插件完成匹配和业务处理，返回标准回复或待入队任务。
5. 出站能力根据渠道类型发送消息，插件不直接调用微信、企微或 Telegram 客户端。
6. 执行结果写入插件执行日志和小时聚合，日志不记录密钥、完整授权头或第三方响应中的敏感字段。

## 定时插件流程

为定时插件增加统一的 `plugin_scheduled_action` 任务类型。任务载荷只保存租户 ID 之外的业务定位信息，例如绑定 ID、动作代码、目标会话和非敏感参数；Worker 从任务所属租户上下文重新加载绑定和密钥。

同一绑定、动作和计划时间使用唯一幂等键，避免服务重启或重复扫描造成双重推送。外部调用失败按插件声明的重试策略处理，可能产生重复副作用的发送或兑换动作默认不自动重试。

## 插件迁移批次

### 第一批：基础能力与已有插件清理

- 增加敏感配置加密存储和表单保存能力。
- 清除目录内置共享凭证。
- 增加统一外部 HTTP、插件状态、调度和标准回复接口。
- 对照 A-BOT 最新版本审核现有 21 个插件，并按插件分别提交差异修复。

### 第二批：轻依赖插件

- `epic_free`
- `github_opengraph`
- `robot_menu`
- `gscore_adapter`

这些插件优先验证命令匹配、外部读取、菜单生成和标准媒体回复，为后续复杂插件提供稳定样例。

### 第三批：租户自备外部服务

- `ai_gen_image`
- `maibot_adapter`
- `codex_quota_allocator`
- `newapi_coupon`

这些插件必须在配置完整且连接检查成功后才允许启用。所有外部消费由租户自己的服务和账户承担，平台记录调用次数、耗时和失败状态，但不代扣或共享上游密钥。

### 第四批：数据分析插件

- `daily_ranking`
- `dota2_stats`
- `member_context`
- `member_roast`
- `value_rank`

这些插件复用 SaaS 消息、联系人、积分和统计模型。A-BOT 专用表只作为业务规则参考，不复制跨租户主键、全局排行或 Redis 缓存结构。

### 第五批：状态型业务插件

- `fun_command_play`
- `xiuxian`

状态表必须继承租户归属，并建立租户内唯一约束。涉及积分、物品、交易或转账的操作使用数据库事务和幂等业务键，禁止依赖进程内锁保证正确性。

## 安全与性能

- 所有插件数据库访问必须运行在 `tenant_scope` 和租户会话中。
- 插件配置接口不接受客户端提供的租户 ID。
- 敏感字段回显为空，只显示是否已配置；空提交保留现有密文，显式清除动作删除密文。
- 外部 HTTP 默认限制连接时间、总时间、响应体大小和重定向次数。
- LLM、图片生成、额度调整、领券和高频查询按租户、绑定、用户或群建立限流。
- 大型报告和图片生成进入任务队列，消息接收主链路只返回处理中状态或异步结果。
- 插件异常相互隔离，单个插件失败不得中断后续允许继续执行的插件或其他租户任务。
- 日志和审计只记录插件代码、绑定、动作、耗时、状态和脱敏错误摘要。

## 错误处理

配置缺失返回明确的“需要配置”状态，不尝试公共默认值。第三方鉴权失败、额度不足、限流、超时和响应格式错误分别归类，便于租户定位自己的服务问题。

消息插件失败时不发送技术堆栈给最终用户。运行页可以展示脱敏错误摘要，完整异常只进入平台日志。具有外部副作用的动作在无法确认执行结果时进入人工确认状态，不自动重复执行。

## 验证策略

当前阶段以功能迁移为主，每次提交只运行与本次插件直接相关的轻量验证：

- `config.toml` 解析和目录发现。
- 插件 matcher、核心业务函数和标准回复测试。
- 敏感配置不进入普通 JSON、HTML、日志和任务载荷的测试。
- 租户 A 不可读取或执行租户 B 绑定与业务数据的定向测试。
- 外部 HTTP 使用本地桩验证超时、鉴权失败和正常响应。
- 定时插件验证幂等入队和任务归属。

每完成一个插件执行一个中文 commit，并在提交说明中如实记录实际运行的轻量测试。15 个新插件和 21 个已有插件审核完成后，再集中执行插件目录、租户隔离、消息派发和任务队列的组合验证。

## 完成标准

- 15 个新插件均可被目录发现、绑定、配置、启停和执行。
- 21 个已有插件均完成与 A-BOT 最新版本的逐项审核并记录结果。
- 目录和数据库不存在可用的共享插件凭证明文。
- 租户可以维护自己的外部服务地址和密钥，并看到是否配置、连接状态和脱敏错误。
- 插件不导入 A-BOT 运行时、数据库、Redis 管理器或微信客户端。
- 微信 iPad、微信 Windows、企业微信和 Telegram 使用同一标准插件回复契约。
- 定时、数据分析和状态型插件遵守租户隔离、幂等和审计要求。
- 4 个单机管理插件的能力已由 SaaS 原生页面、统计和平台运维边界覆盖。
