# 曜枢 AI 营销、注册、计费与机器人额度 MVP 设计

## 1. 背景与目标

`multi-bot-saas` 已具备租户、员工、套餐、订阅、权限、数据库迁移和独立部署基础，但当前入口仍以后台管理为中心，租户需要由平台管理员人工创建，也没有公开营销页面、自助注册、订单和付款审核闭环。

本阶段保持仓库名、内部模块名和现有接口命名不变，仅增加对外品牌“曜枢 AI”。产品定位为全渠道智能机器人运营平台，不限定企业微信，也不让商业化核心逻辑依赖具体 Provider、渠道或设备实现。

首版目标是形成可以真实使用的最小商业闭环：

```text
营销首页 → 查看套餐 → 企业注册 → 7 天试用
→ 选择套餐 → 创建订单 → 上传付款凭证
→ 平台审核 → 自动开通订阅与机器人额度
```

## 2. 首版范围

### 2.1 包含

- 曜枢 AI 公开营销首页；
- 公开套餐页；
- 企业主手机号注册与登录；
- 原租户员工登录入口继续保留；
- 注册后自动创建一个企业租户、企业所有者和 7 天试用订阅；
- 入门版、标准版、专业版月付和年付套餐；
- 人工付款订单、付款流水号和付款凭证上传；
- 平台管理员审核订单并原子开通或续期；
- 通用机器人账号绑定和设备试用防重复；
- 企业主查看当前套餐、机器人额度和订单历史；
- 平台管理员查看订单、审核订单和执行受控解绑；
- 关键操作的平台审计日志；
- 桌面和移动端基础适配。

### 2.2 不包含

- 微信支付、支付宝或银行卡自动支付；
- 发票、退款、优惠券和促销码；
- 按天差价或复杂升降级；
- 一个手机号管理多个企业；
- 用户自助换绑申请；
- 多支付方式管理后台；
- 将营销站拆成独立前端或独立服务；
- 重命名仓库、数据库、Python 包或现有内部 API。

## 3. 产品和计费规则

### 3.1 品牌和客户

- 对外品牌：曜枢 AI；
- 产品类别：全渠道智能机器人运营平台；
- 首要客户：中小企业客服、社群运营和自动化团队；
- 官网主行动：免费试用 7 天；
- 官网次行动：查看套餐。

### 3.2 默认套餐

| 套餐 | 机器人额度 | 月付 | 年付 |
| --- | ---: | ---: | ---: |
| 入门版 | 1 | ¥99 | ¥990 |
| 标准版 | 3 | ¥259 | ¥2590 |
| 专业版 | 10 | ¥699 | ¥6990 |

年付按 10 个月价格计算。所有价格和额度保存在数据库中，平台管理员可以修改，页面不得写死订单金额。

### 3.3 试用

- 注册成功后立即开通 7 天试用；
- 试用包含 1 个机器人额度；
- 到期后保留数据和绑定关系，业务写操作进入只读状态；
- 同一个设备在全平台只能领取一次试用；
- 试用期间用户不能自行更换机器人账号或设备。

### 3.4 订单与订阅

订单状态只保留首版需要的五种：

- `pending_payment`：订单已创建，等待付款；
- `payment_submitted`：用户已提交付款信息；
- `approved`：平台已审核并完成开通；
- `rejected`：付款信息被驳回，可以重新提交；
- `cancelled`：用户取消且不再处理。

订单金额、套餐额度和计费周期必须由服务端根据套餐计算。客户端只能提交套餐 ID 和月付/年付周期，不能提交可信金额。

审核通过时必须在一个事务中：锁定订单、校验状态、结束旧的当前订阅、创建新订阅、更新订单、调整有效额度并写平台审计。重复审核已经完成的订单返回幂等结果，不能重复延长订阅。

续费从当前到期时间或审核时间中的较晚时间向后延长。购买更高套餐时额度立即提升，并在原到期时间之后增加一个完整周期。首版不提供主动降级入口。

## 4. 身份与注册

### 4.1 企业主账号

现有 `TenantUser` 增加：

- `mobile`：可空但全局唯一，公开注册的企业主必须填写；
- `is_owner`：标识企业所有者；
- `mobile_verified_at` 暂不增加，首版不接短信验证。

公开企业主使用手机号和密码登录。原租户员工继续使用企业编码、用户名和密码登录，两种登录最终都创建现有租户会话，不引入第二套浏览器会话。

### 4.2 注册事务

注册请求依次校验手机号、企业名称、联系人、密码和图形验证码，然后在同一个事务中：

1. 生成不可预测且唯一的企业编码；
2. 创建 `Tenant`；
3. 创建角色为 `tenant_admin` 的企业所有者；
4. 创建 7 天试用订阅；
5. 写平台审计；
6. 提交后创建登录会话并进入新手引导。

任一步失败必须回滚全部记录，不能留下没有管理员、没有订阅或无法登录的半成品租户。

## 5. 数据模型

### 5.1 `SaasPlan` 扩展

- `bot_limit`：通用机器人额度；
- `monthly_price_cents`：月付金额，单位分；
- `yearly_price_cents`：年付金额，单位分；
- `trial_days`：试用天数；
- `is_public`：是否在公开套餐页展示；
- `is_featured`：是否标记为推荐套餐；
- `display_order`：公开展示顺序。

旧 `provider_node_limit` 在迁移期继续保留供现有功能使用，并用数据迁移回填 `bot_limit`。新增商业化逻辑只读取 `bot_limit`，后续再单独迁移适配器额度。

### 5.2 `BillingOrder`

- 订单号、租户、套餐、计费周期；
- 服务端固化的机器人额度和金额快照；
- 状态、付款流水号、付款凭证私有路径；
- 用户提交时间、审核人、审核时间和驳回原因；
- 审核后创建的订阅 ID；
- 创建时间和更新时间。

订单号使用高熵随机值。付款凭证不能通过公开静态目录访问，只允许当前租户和平台管理员通过受控下载接口读取。

### 5.3 `BotBinding`

- 租户 ID；
- `adapter_type`：渠道或执行适配类型；
- `bot_account_id`：规范化后的外部机器人账号 ID；
- 显示名称；
- `device_fingerprint_hash`：设备指纹不可逆摘要；
- `status`：`active`、`disabled` 或 `released`；
- 绑定和释放时间；
- 释放操作人和原因。

`(adapter_type, bot_account_id)` 在全平台只能有一个有效绑定。一个设备只能归属于一个企业，但付费企业可以在同一设备上绑定套餐额度内的多个机器人账号。

### 5.4 `DeviceTrialClaim`

- 全局唯一的设备指纹摘要；
- 首次领取试用的租户 ID；
- 领取时间。

该记录永久保留，不因机器人解绑、租户到期或账号停用而删除。

## 6. 模块边界

新增模块：

```text
app/web/public_site.py
app/web/billing.py
app/web/platform_billing.py
app/services/registration.py
app/services/billing.py
app/services/bot_entitlements.py
app/services/payment_gateways/base.py
app/services/payment_gateways/manual.py
```

- `public_site` 只负责公开展示和注册表单；
- `billing` 只处理当前租户的订单与额度页面；
- `platform_billing` 只处理平台管理员审核；
- `registration` 管理租户注册事务；
- `billing` 管理价格、订单和订阅状态；
- `bot_entitlements` 管理通用机器人绑定、额度和设备防重复；
- `PaymentGateway` 统一付款说明和付款结果结构；首版 `ManualPaymentGateway` 不执行外部网络请求。

核心订单和额度服务不能导入 Provider 客户端、Provider API 或具体渠道 Adapter。

## 8. 页面结构与视觉

### 8.1 营销首页

```text
导航：曜枢 AI / 产品能力 / 使用流程 / 套餐价格 / 登录 / 免费试用

首屏：
曜枢 AI
一个后台，统一运营所有智能机器人
管理多渠道接入、自动化任务、团队权限和机器人额度
[免费试用 7 天] [查看套餐]

后续：能力带 → 使用流程 → 控制台实景 → 套餐预览 → FAQ → 最终 CTA
```

首屏使用实际控制台画面作为全幅背景，文字直接覆盖在背景上，不放入卡片。首屏底部必须露出下一段内容。页面使用石墨黑、白色、青绿色和少量蓝色，不使用紫色渐变、装饰光球或卡片嵌套。

### 8.2 注册与登录

- 注册页使用单列紧凑表单；
- 登录页默认展示企业主手机号登录；
- 员工登录使用明确的独立入口；
- 页面不展示内部租户 ID、套餐 ID 或可由客户端伪造的身份字段；
- 移动端按钮和输入框保持稳定宽度，不出现文字溢出。

### 8.3 套餐与订单

- 套餐页展示三个可比较套餐，标准版为推荐项；
- 月付和年付使用分段控制器；
- 订单页展示服务端价格快照、付款说明、二维码或银行信息、流水号和凭证上传；
- 订单状态使用明确文本，不把“已提交付款凭证”表述为“已支付成功”；
- 额度页显示当前套餐、到期时间、已用/总额度和绑定清单。

## 9. 安全和异常处理

- 手机号、订单号、机器人账号和设备指纹均由服务端规范化；
- 密码继续使用现有 Argon2id 哈希和数据库会话；
- 注册和登录使用现有验证码、限速和统一错误提示；
- 上传凭证限制扩展名、MIME、文件大小和解析后的真实路径；
- 订单金额只由服务端套餐计算；
- 审核接口校验平台 CSRF，并使用事务和行锁保证幂等；
- 机器人绑定校验当前有效订阅和 `bot_limit`；
- 日志、审计和订单结果不得记录密码、设备原始指纹或付款凭证正文；
- 所有租户页面和文件读取继续使用可信会话恢复的 `tenant_id`。

## 10. 轻量测试策略

首版只运行与本阶段直接相关的轻量测试：

- 注册成功、重复手机号和事务回滚；
- 试用订阅和企业所有者创建；
- 套餐公开展示和服务端价格计算；
- 订单状态流转和重复审核幂等；
- 付款凭证租户隔离；
- 机器人额度限制；
- 机器人账号跨租户唯一；
- 设备试用全局去重和设备单租户约束；
- 公开路由与租户/平台认证边界；
- 首页、注册、登录、套餐和订单的桌面/移动端浏览器检查；
- `git diff --check`、Alembic 单一 head 和 Compose 配置检查。

本阶段不以全量历史测试通过作为提交门禁。发现与当前功能无关的历史问题只记录，不扩大修改范围。

## 11. 提交与发布

研发按模型迁移、注册认证、订单审核、机器人额度、营销页面、浏览器验收和部署分阶段提交。每次提交使用中文说明，并记录实际执行的轻量测试。

发布前在 `192.168.2.142` 备份环境配置和 MariaDB，使用 `git pull --ff-only`、Alembic 升级和 Docker Compose 重建应用。验收至少确认：公开首页、注册、企业主登录、员工登录、套餐、订单提交、平台审核、额度生效、健康和就绪探针，以及旧 `8180` 服务不受影响。
