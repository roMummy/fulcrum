# 曜枢 AI 北欧极简 UI 重构设计

## 1. 目标

本次重构覆盖营销页、注册登录页、企业租户后台和平台方后台。目标不是给现有页面简单换色，而是重新建立统一的信息层级，解决页面整体平铺、卡片数量过多、卡片套卡片、边框与分割线过密的问题。

重构只调整视觉与页面组织方式，不修改现有路由、认证边界、权限判断和业务数据流。企业租户后台与平台方后台继续保持独立身份、独立导航和独立数据权限。

## 2. 参考风格与落地原则

参考 StyleKit 的 Scandinavian Minimalism 风格，但根据 SaaS 工作台的使用密度进行产品化调整：

- 使用暖灰白背景、炭灰正文、低饱和苔绿和少量自然木色。
- 使用轻盈但可读的字重，中文正文不使用影响识别的超细字体。
- 通过留白、字号、背景明度和内容宽度建立层级，减少依赖边框。
- 阴影默认取消，仅在模态框等必须表现空间层级的组件中使用极轻阴影。
- 圆角控制在 2 至 6 像素，不使用大圆角卡片和胶囊形导航。
- 动效只使用颜色、边框和亮度渐变，不使用弹跳、缩放和明显位移。
- 所有交互组件保留明确的 hover、active 和 focus-visible 状态。

## 3. 全局视觉系统

### 3.1 色彩

- 页面背景：`#f5f0eb`
- 主内容表面：`rgba(255, 255, 255, 0.72)`
- 主文字：`#3d3d3d`
- 次级文字：使用比参考木色更深的色值，保证中文小字可读性
- 品牌强调：`#5a7a6b`
- 辅助强调：`#607683`
- 自然木色：`#a89279`，仅用于眉题、装饰编号和低优先级信息
- 分隔色：`rgba(168, 146, 121, 0.28)`

成功、警告、危险和信息状态继续使用可区分的语义色，但降低饱和度，并确保文字对比度满足可读要求。

### 3.2 排版

全局继续使用系统可用字体，优先 `Avenir Next`、`PingFang SC`、`Noto Sans SC` 和 `Segoe UI`。标题采用轻到中等字重，正文采用常规字重，数字指标使用中等字重。英文眉题不再大面积使用全大写与过宽字距。

后台页面标题保持工作台尺度，不使用营销页级别的超大字号。营销页首屏标题承担品牌和产品定位，后台标题只承担页面定位。

### 3.3 间距与边界

营销页面使用较大纵向留白；后台使用中等密度，保证列表、表单和监控信息可快速扫描。所有内容使用稳定的最大宽度和响应式边距。

边框仅用于以下场景：

- 表格外框与必要的行分隔；
- 输入框、选择器和代码编辑器；
- 模态框、通知和危险操作区域；
- 需要明确边界的重复业务对象。

普通页面区块、标题区域、指标区域和详情字段不再逐项加框。

## 4. 页面架构

### 4.1 营销站点

营销页使用全宽内容带和受控内容宽度，不把每个区块做成浮动卡片。首屏直接展示“曜枢 AI”品牌和真实控制台画面，使用暖色背景与清晰产品信息，取消深色遮罩和强对比覆盖层。

产品能力、使用流程和套餐信息通过留白、序号、细分隔和背景明度组织。套餐仍然是可比较的重复对象，可以保留轻量表面，但不使用厚边框和悬浮阴影。

### 4.2 注册与登录

认证页采用安静的双栏结构：一侧提供品牌和上下文，一侧承载表单。表单区域不再表现为厚重的大卡片，输入框采用简洁底线或轻边界形式。移动端按“品牌上下文、表单、辅助入口”的顺序自然堆叠。

### 4.3 企业租户后台

桌面端使用窄侧边导航与主工作区，移动端使用紧凑顶部栏和可展开导航。页面标题、介绍和主要操作直接位于内容顶部，不再包入卡片。

仪表盘指标使用连续数据带；图表、排行榜和告警按信息组呈现。列表页以单一表格表面为主，详情页使用定义列表和自然分栏。企业租户只看到企业运营、机器人、渠道、插件、消息、团队与套餐额度相关功能。

### 4.4 平台方后台

平台后台复用同一视觉系统和壳层结构，但使用独立的平台身份标识与菜单。平台页面聚焦租户、员工、套餐、订单、机器人绑定、监控和日志，不混入企业业务入口。

平台总览使用连续指标和一个主要数据表，不再为每个指标创建独立卡片。

## 5. 组件规则

- 主按钮使用炭灰底色，关键营销行动可使用苔绿色；次按钮使用透明背景和细边界。
- 导航使用文字、图标和选中标记，不使用胶囊底色。
- 状态标签使用小圆角矩形和低饱和底色，不使用全圆角胶囊。
- 表格使用轻表头背景、克制行分隔和稳定列间距；移动端必要时转为纵向记录列表。
- 表单标签、帮助信息和错误信息保持明确层级；错误信息不得仅依赖颜色表达。
- 弹窗保留真实空间边界和焦点管理，危险操作继续展示明确确认信息。
- 空状态只说明当前状态和下一步操作，不添加装饰性大卡片。

## 6. 数据流与错误处理

本次重构不改变后端数据流。模板继续消费现有上下文变量，表单继续提交到现有接口，CSRF、会话、权限判断和确认流程保持不变。

通知、字段错误、空状态、加载失败、禁用状态和危险操作必须在新视觉系统下保持清晰。禁止为了视觉简洁隐藏安全提示、权限提示、额度限制和不可逆操作说明。

## 7. 实施边界

- 不新增前端框架，不引入仅用于换肤的运行时依赖。
- 不建立旧样式兼容层，不保留废弃选择器的别名覆盖。
- 修改共享壳层和样式时同步迁移模板语义，删除确认无用的旧样式。
- 保持内部项目命名 `multi-bot-saas`，对外品牌继续使用“曜枢 AI”。
- 不修改当前业务模型、权限边界和 Provider 抽象方向。

## 8. 验证策略

当前研发阶段以完成重构为主，只执行与本次改动直接相关的轻量验证：

- 模板语法与关键页面渲染检查；
- CSS 基础静态检查和废弃选择器检查；
- 营销首页、登录注册、企业总览、平台总览及代表性列表/详情页接口检查；
- 桌面端与移动端截图检查，重点确认内容不重叠、文字不溢出、导航可用、表格可读；
- 键盘焦点和关键表单交互检查。

本次不执行全量历史回归、完整性能门禁和全量端到端测试。
